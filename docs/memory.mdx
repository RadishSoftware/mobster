Mobster's agent can remember what you tell it: where your gym is, how you sign your texts, that Kate Bell is your sister. You write it in your own words, or accept a suggestion Mobster makes from something you typed. It stays on this Mac, and a task sends only the few things it needs to your AI account.

<Note>Mobster never remembers passwords, codes or card numbers. What you write is saved as you write it, a suggestion only when you choose **Remember**. What Mobster learns from a task or a check is saved too, shown as **New since you last looked**, and you can **Keep** or **Forget** each fact. A forgotten fact isn't learned again for 90 days. Turn **Suggest things to remember** off and Mobster learns nothing from use.</Note>

## In the Mac app

Open **Memory** in Settings, under Your agent, or from ⌘K to see what Mobster knows. It opens inside Settings, and **Back** at the top of the sections returns you to where you were before Settings. **New since you last looked** lists learned facts with **Keep** and **Forget**, and suggestions from your words with **Remember** and **Not now**. After three seconds on the loaded page, the new facts count as seen.

The remaining facts are grouped by kind. Search the list or narrow it to a saved profile, workflow, project, app or phone. Facts already scoped to a profile and workflow show both. Each row names its source, last use and scope. Pin, edit or forget a fact from its row. **Add something** ends the list. Forget prevents relearning for 90 days; the toast offers **Undo**.

A step that used a saved fact shows "from memory" after its time. Open the step to read the fact: "From memory: Insights is under Professional dashboard". If the fact caused a wrong step, choose **Forget**. Mobster won't learn it again for 90 days. **Undo** restores it.

Under a finished task, open the memory line to see which facts it used and learned. Keep useful facts or forget ones that caused mistakes.

**How tasks use it**, at the foot of the same page, keeps these controls:

- **Use memory in tasks.** On by default. Off, no task gets anything Mobster remembers.
- **Suggest things to remember.** On by default. Off, Mobster stops learning from use and suggesting facts from your words.
- **Export as Markdown** saves everything to a file you can read or keep.
- **Delete everything Mobster remembers** asks first, then deletes every fact and suggestion. These switches stay as they are.



In a conversation, a suggestion shows as a card under your message: **Remember this?** with **Remember**, **Edit** and **Not now**. A preference or a name ("I always…", "Call me…") is suggested pinned, and the card names the scope where it applies. A card whose suggestion has expired or was deleted says so instead of offering the buttons.

## What Mobster learns

Every fact has a **kind**, a **source**, a **scope** and a **confidence**:

| Kind | Example |
| --- | --- |
| `path` | In Instagram, Insights is under the profile's menu, then Professional dashboard |
| `place` | The test account's sign-in is in Settings, second row |
| `value` | The test account is qa+ios@radish.software |
| `preference` | Replies as @getmobster are warm and short |
| `rule` | Never like or follow from @getmobster |
| `structure` | Settings opens General with About first, then Software Update |
| `device` | This iPhone 16 is on iOS 18.3.1 |
| `outcome` | The Skip on your app's paywall moved in build 412 |
| `cost` | Reading 20 Reels on this phone costs about \$0.04 |
| `repo` | The scheme is IceCubesApp, the bundle is com.thomasricouard.IceCubesApp |

The source is `user` (you), `run`, `lesson` (something you taught), `check`, `repo` or `profile`. The scope is everywhere (`global`), one `app:<bundle>`, `phone:<id>`, `project:<id>`, `profile:<id>`, `workflow:<id>`, or `profile:<id>/workflow:<id>`. The last scope requires both saved records on the task. A task gets at most 12 eligible facts. Pinned facts still require their scope to match. Unknown scopes are shown but never sent to a task.

A profile scope follows the saved profile record when you edit its handle or app. Create a new saved profile for a different identity. A workflow scope follows its saved workflow ID. Deleting a workflow makes its facts inactive; importing an identical portable workflow can restore the same ID and those facts. This limits saved-memory selection. Earlier messages and results remain part of a shared conversation.

The Memory page lists a saved profile's voice and signature as profile-sourced facts. Edit those words in **Profiles**. A task reads the profile text captured when that task was admitted, even if you edit the saved profile while it waits to run. Profile-sourced mirror facts are not added to its memory prompt or its memory preview; facts you wrote yourself for that profile still are. Pinning or editing a mirror in the memory API does not change the captured profile text.

A task stages what it learned and Mobster saves it when the task finishes with a result you didn't dispute. The same fact told twice is one fact. Learning can update an unreviewed keyed value of the same kind; it never rewrites a kept, pinned or edited fact. Saving a profile explicitly updates its own voice and signature mirror facts from the profile editor. Only you or a profile can write a `rule` or a `preference`: text read from a screen is data, so a run, a check or the repo can't give Mobster an order. Learned task and check facts enter the prompt as fenced data, separate from facts you wrote yourself. A `cost` is for estimates and never goes to the model. A fact nobody used for 90 days is flagged `stale` so the app can offer to remove it.

### Who teaches it

| Source | What it writes | When |
| --- | --- | --- |
| A finished task (`run`) | The path it recorded for the task ("In Settings, “open General, then About” goes: tap “General”, then tap “About”"), what App X-ray mapped, what the task cost and took | When the task completes. A task that stops, fails or isn't confirmed saves nothing. |
| A lesson you taught (`lesson`) | The path it took and the screens it passed through | Held when you stop the lesson, saved when you save it, dropped when you discard it |
| A check suite (`check`) | What each passing check walks, and each heal ("“Skip” is now “Not now”") | When `mobster test` finishes |
| The project (`repo`) | The scheme and bundle, the checks and the phones they run on | When a suite or a PR build runs, and when a project's `.mobster/memory.yaml` is read |
| A profile (`profile`) | Its voice and signature, as facts you edit where you edit the profile | When you save the profile. Removing the profile removes them. |
| The phone | Its model and iOS version | When a task starts on it |

Typed text is never kept in a path, only the names of the things tapped. A task's events say when a step acted on a fact it was given: `from_memory {step, index, ids}`. When a task finishes, `learned {runId, facts}` goes on the `memory` topic.

### `.mobster/memory.yaml`

What Mobster learns about a project is written to `.mobster/memory.yaml` in the project, so it travels with the repo and shows in pull requests. Only project facts from the repo, a check, a task or a lesson go there. What you wrote yourself, a profile's voice, a phone's facts and anything with a home folder or a device ID in it stay on this Mac. Forgetting a project fact also removes it from this file. A teammate's file is read as `repo` facts at a confidence of 0.6 or less, and it can't set a rule or a preference.

```yaml
version: 1
facts:
  - kind: repo
    text: The scheme is IceCubesApp and the bundle is com.thomasricouard.IceCubesApp.
    key: repo:scheme
    source: repo
    confidence: 0.9
```

A project is named by the run field `project`, an id or `{id, path}`. The Projects page links the id to its folder with `POST /api/memory/projects`.

If the store file is damaged, Mobster moves it to `memory.sqlite3.corrupt-<time>` beside it and starts empty. **Delete everything** removes that file too.

## Which things go with a task

A task gets at most 12 things, and at most 1,200 characters of them, as one short section of what Mobster's agent reads before it starts:

- **Pinned** things go with every eligible task in their scope. Pin the ones that always matter there, such as "Call me Sam" or "I prefer short replies". You can pin up to 10, of up to 1,000 characters together.
- **The rest** go with tasks that share words with them: "When does my gym close?" gets "My gym is the one on 5th Street".
- **Things for one app** go only when that app is in the task: it's the app you started in, the app the conversation was last in, or the task names it ("Open Messages and…").

Memory goes with tasks you start in the Mac app or `mobster chat`, and with your workflows. It never goes with tasks another agent starts over MCP or the HTTP API. Tasks in the terminal UI (`mobster`) don't get it yet, and don't make suggestions.

A task's events say which things it used, by ID only (`memory_used`), never their words. What the agent reads says these are your words and that the screen wins when they disagree, so an old fact never overrides what's in front of it.

## Suggestions

Mobster suggests something to remember when what you write says it plainly, sentence by sentence. It never calls a model to do it, so suggestions cost nothing and change nothing about the task:

| You write | Mobster suggests |
| --- | --- |
| Remember that my gym is the one on 5th Street | My gym is the one on 5th Street |
| my sister's name is Kate Bell | My sister's name is Kate Bell |
| I always take the window seat | I always take the window seat (pinned) |
| Call me Sam | Call me Sam (pinned) |

It never suggests a passing state ("my battery is low"), a question ("what time does my gym close?"), something inside a task ("text Sam that my train is late"), a reminder ("remember to buy milk") or anything that looks like a password, code or card number. It reads only what you type in a task or send while one works, never what's on the screen or what another agent sends.

A suggestion waits 14 days. **Not now** means Mobster won't suggest the same words again for 90 days, and it keeps only a fingerprint of them, not the words.

## `mobster memory`

The CLI reads and writes the same file as the Mac app.

```sh
mobster memory                       # the same as: mobster memory list
mobster memory add "My gym is the one on 5th Street"
mobster memory add "Sign my texts with – Sam" --app com.apple.MobileSMS --pin
mobster memory list --new            # what Mobster learned since you last looked
mobster memory list --scope project:daybreak --kind repo
mobster memory keep 3f9c2a1b7d0e
mobster memory forget 3f9c2a1b7d0e   # the same as rm; not learned again for 90 days
mobster memory list --json
mobster memory pin 3f9c2a1b7d0e
mobster memory unpin 3f9c2a1b7d0e
mobster memory rm 3f9c2a1b7d0e
mobster memory export --output memory.md      # --json for every fact's kind, source and scope
mobster memory clear                 # asks you to type "delete everything"; --yes skips it
```

Adding a thing and listing what Mobster remembers print this (Mobster 0.4.0, a new empty memory, 17 Oct 2026; the id is new each time):

```text
$ mobster memory add "My gym is the one on 5th Street"
Mobster will remember: My gym is the one on 5th Street  (66b31285b129)
$ mobster memory
66b31285b129  My gym is the one on 5th Street

1 thing. Pinned ones go with eligible tasks in their scope; the rest go with tasks that fit. Everything stays on this Mac.
```

With nothing remembered, `mobster memory` prints `Mobster doesn't remember anything yet. Tell it something:` and the `add` command above.

Exit codes: 0 done, 1 refused or not found, 2 usage, 3 memory can't be opened here (saved by a newer Mobster, or no home folder).

## Where it's kept

One SQLite file, `~/Library/Application Support/app.mobster.desktop/memory/memory.sqlite3`. Its folder is readable only by you (0700), and the file too (0600). Each time Mobster opens it, it tightens an older store to those modes, and it refuses a store that is a symlink or belongs to another user (memory is then unavailable, error `memory_unavailable`). The Mac app, `mobster serve` and `mobster memory` all use it. A source checkout keeps its own at `mobile_agent/.state/data/memory/`, and so does each dev window, so a test there never writes to what your installed Mobster remembers. `MOBSTER_MEMORY_DIR` moves it, which is meant for tests.

Deleting everything removes the words from the file, not only from the list.

## HTTP API

Under `/api/memory`, with the same token as the rest of the API ([the HTTP API](/scripting#the-http-api)). Each body is JSON, and each error is a sentence with a code.

| Route | Body or query | Answer |
| --- | --- | --- |
| `GET /api/memory/facts` | `?scope=<scope>[,<scope>]&kind=&source=&new=1&q=<words>` | `{facts, count, limits, kinds, sources, scopes}` |
| `POST /api/memory/facts` | `{text, scope?, kind?, pinned?}` | 201 `{fact}`, 400 `secret`, `too_long`, `invalid_text`, `invalid_scope`, `invalid_kind`, 409 `duplicate` (with the `fact`), `memory_full`, `too_many_pinned`, `pinned_too_long` |
| `POST /api/memory/facts/{id}` | `{text?, scope?, kind?, pinned?}` | `{fact}`, 404 `not_found`. Editing an ordinary fact keeps it and stops runs rewriting it; edit profile-sourced mirrors in Profiles |
| `DELETE /api/memory/facts/{id}` | | `{deleted: true}`, 404. Forgets the fact, as `forget` does |
| `POST /api/memory/facts/{id}/keep` | | `{fact}` |
| `POST /api/memory/facts/{id}/forget` | | `{forgotten: true, fact}` |
| `GET /api/memory/new` | `?scope=` | `{facts, count}`: learned since `looked`, not kept |
| `POST /api/memory/looked` | | `{lookedAt}` |
| `GET /api/memory/preview` | `?goal=&app=<bundle>&profile=&project=&phone=` | `{facts, chars, limits}`: what a task would get; marks nothing used |
| `GET /api/memory/run` | `?runId=<id>` | `{used, learned, pending, learnedCount}` |
| `POST /api/memory/projects` | `{id, path}` | `{linked, moved, imported}`: links the project to its folder, moves facts learned before it had an id, reads `.mobster/memory.yaml` |
| `GET /api/memory/proposals` | `?thread=<id>&status=pending\|accepted\|dismissed\|expired\|all` | `{proposals}` |
| `POST /api/memory/proposals/{id}` | `{accept, text?, pinned?}` | `{proposal, fact}`, 409 `not_pending` |
| `GET /api/memory/settings` | | `{settings: {useInTasks, suggest}, count, limits}` |
| `POST /api/memory/settings` | `{useInTasks?, suggest?}` | `{settings}` |
| `POST /api/memory/clear` | `{confirm: "delete everything"}` | `{deleted: {facts, proposals}}` |
| `GET /api/memory/export` | `?format=json` for data | Markdown (`text/markdown`), or `{version, facts}` |

A fact is `{id, text, scope, scopeKind, scopeId, app: {bundleId, name} | null, kind, source, ref, confidence, pinned, kept, edited, new, stale, createdAt, updatedAt, lastUsedAt, uses}` (times in milliseconds). `ref` names where it came from: `runId`, `lessonId`, `checkPath`, `repo` or `profileId`. A file saved by a newer Mobster answers 503 `newer_data`.

**Events.** The bus topic `memory` (`GET /api/events?topics=memory`) carries `fact_changed {op: added|updated|kept|forgotten|deleted|cleared, fact|id}`, `proposal_created {proposal}`, `proposal_resolved {id, accepted, factId?}` and `settings_changed {settings}`. A run's own events carry `memory_used {ids}`.

**Conversations.** A suggestion from a task in a conversation is posted to it as a thread item of kind `memory_proposal`: `{proposalId, text, scope, app, pin, status, runId, expiresAt}`. Answering it updates the item's `status` (and `text` and `factId` once remembered).
