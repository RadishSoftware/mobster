The generated workflow runs the standalone `mobster-cli==0.4.0` package through uv. It needs macOS, Xcode and an iOS Simulator runtime. The Mac app is not required.

Bitrise builds on macOS machines it hosts. `mobster ci init --host bitrise` writes a workflow with the steps. [CI](/ci) has the parts every host shares.

## Set it up

```sh
mobster ci init --host bitrise
```

It writes `bitrise.yml`. When that file exists, it leaves it as it is and writes the `mobster` workflow to `.mobster/hosts/bitrise.yml` for you to merge. Then add `ANTHROPIC_API_KEY` for checks with steps as a Secret of the Bitrise app, trigger the `mobster` workflow on pull requests, commit the file and open a pull request.

The workflow clones the repository, installs uv with Homebrew and runs the pinned standalone CLI, runs `mobster sim doctor --fix`, runs `mobster ci run`, and deploys `.mobster/ci` as the build's artifacts even when a check fails. The target branch comes from `BITRISEIO_GIT_BRANCH_DEST`. Bitrise gets no comment from Mobster: GitHub and GitLab are the hosts where `mobster ci comment` posts.

## Credentials

Launch-only checks need no model key. Set `ANTHROPIC_API_KEY` for checks that use Smart. The standalone CLI requires no Mobster account or CI token. If you supply `MOBSTER_CI_TOKEN`, `mobster ci doctor` still validates it. App-bundled commands retain their plan and token checks.

## What this runner doesn't do

A hosted Mac has no iPhone, so the checks run on simulators. To test on a phone, use [a Mac of yours](/ci/mac-runner).
