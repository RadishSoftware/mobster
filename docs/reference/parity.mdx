Each capability is reachable three ways: the `mobster` command, the local API Mobster for Mac uses, and an MCP tool for coding agents. This page lists where each one is, and for every place it isn't, either why Mobster left it out on purpose (**No**) or that it is still to build (**Gap 1 to 3**, 1 first). A test fails when a command, tool or API group ships without a row here, and when a testing capability has no MCP tool and no reason.

## Testing

| Capability | CLI | API | MCP |
|---|---|---|---|
| Run saved checks, with `--locale`, `--a11y`, `--sim`, `--parallel` | `mobster test` | `/api/tests` | `run_tests` |
| Inspect or export a completed local suite | `mobster test capsule` | No. Raw evidence export is an explicit local terminal selection. | No. Agents compare saved suites with compare_test_suites; raw evidence export stays with the person. |
| Compare two exact saved suites | `mobster test compare` | No. The local API shows suite results; paired comparison reads completion-bound local reports. | `compare_test_suites` |
| Run an ordered simulator scenario | `mobster test scenario` | No. Scenario manifests and actor leases are local test-project operations. | No. The person starts the bounded multi-simulator scenario in the terminal. |
| Reduce a controlled local reproducer | `mobster test minimize` | No. The reducer runs bounded local test suites against two explicit app builds. | No. The reducer has no durable MCP job and status interface; run it explicitly in the terminal. |
| Run one check once | `mobster verify` | No. The app starts checks as tasks (/api/runs) and shows results from /api/tests. | `verify_start`, `verify_finish` |
| Record a check from a task | `mobster test record` | `/api/tests` | `save_check` |
| Import Maestro flows as checks | `mobster test import maestro` | **Gap 2.** The app has no import screen yet. | `import_maestro` |
| Reproduce a crash report as a check | `mobster test repro` | **Gap 3.** The app has no crash intake screen yet. | `repro_crash` |
| Add a check from a recipe | `mobster test add` | No. The app writes checks from its editor. | No. An agent writes the check file itself, or saves a task as one with save_check. |
| Test what a pull request changed | `mobster test pr` | No. It runs from the terminal, CI or an agent, where the diff is. | `run_tests` |
| Review and accept healed steps | `mobster test heal` | `/api/tests/heals` | `review_heals` |
| Read each check's history | `mobster test --history` | `/api/tests/history`, `/api/projects` | `test_history` |
| Overnight run: list it, run it now | `mobster test nightly` | **Gap 3.** The app's schedules are for workflows; a nightly suite isn't listed there. | `test_schedule` |
| Scheduled health checks | `mobster test schedule` | `/api/tests/schedules` | No. The scheduler can bind real iPhones; agents run simulator checks with run_tests instead. |
| Project fixtures | `mobster fixtures list`, `mobster fixtures apply` | `/api/tests/fixtures` | No. An agent writes fixture files and runs checks that use them with run_tests. |
| Project deep links | `mobster links list`, `mobster links check` | `/api/tests/links`, `/api/projects` | No. An agent reads .mobster/links.yaml and tests links with run_tests or verify_start. |
| Manage simulators: list | `mobster sim list`, `mobster devices` | `/api/devices` | `list_devices` |
| Manage simulators: prepare and clean up | `mobster sim prepare`, `mobster sim shutdown`, `mobster sim erase`, `mobster sim delete`, `mobster sim prune`, `mobster sim release`, `mobster sim doctor`, `mobster sim biometric` | No. Simulators belong to checks: the app never asks for one by hand. | No. verify_start and run_tests prepare and release simulators themselves; deleting stays with the person. |
| Run checks on every pull request (CI) | `mobster ci init`, `mobster ci run`, `mobster ci comment`, `mobster ci doctor` | No. It runs in CI, on a hosted runner or a Mac of yours, with no app. | No. CI starts it; an agent tests a branch with run_tests pr. |
| Run checks after every Xcode build | `mobster xcode after-build`, `mobster xcode hook`, `mobster xcode unhook` | No. It is a scheme post-action. | No. Xcode starts it; an agent runs run_tests itself. |
| Expo: preview and reload | `mobster expo preview`, `mobster expo reload` | No. The Mac app's tools reach Expo through MCP. | `expo_preview`, `expo_reload` |
| Expo: build, dev server, doctor | `mobster expo build`, `mobster expo dev`, `mobster expo stop`, `mobster expo doctor` | **Gap 3.** No screen starts a dev server. | No. Building and starting Metro are the developer's build step: an agent runs the same commands in its own shell, and expo_preview opens the result. |
| Test credentials for a project (env) | `mobster env list` | `/api/project` | No. The names are in .mobster/env.example, which an agent reads as a file; the values stay in the Keychain. |
| Set and remove a project's test credentials | `mobster env set`, `mobster env unset` | `/api/project` | No. Secrets are typed by the person: an agent never sets or clears one. |

- **Run saved checks, with `--locale`, `--a11y`, `--sim`, `--parallel`.** The API serves results (recent suites, a task as a check); the Mac app starts a check as a task.
- **Read each check's history.** GET /api/projects/\{id\}/tests includes each check’s last 20 results.

|---|---|---|---|

| System alerts, Home, buttons | `mobster phone button` | No. The app acts through tasks. | `alert`, `home`, `press_button` |
| Open a link or an app | `mobster phone open` | No. The app opens things through tasks. | `open_url`, `launch_app` |
| Install a local build | `mobster phone install` | `/api/phone` | `install_app` |
| Clipboard | `mobster phone clipboard` | `/api/phone` | `set_clipboard` |

| Photos both ways | `mobster phone photos` | `/api/phone` | `send_media`, `pull_media` |
| Record the phone's network | `mobster phone network` | `/api/phone` | No. It records everything the phone sends, so the person starts it. |
| Record the phone's screen | `mobster phone record` | `/api/phone` | **Gap 3.** An agent can't record a clip of the phone. |
| Display settings | No. A task sets it: mobster run "Turn on Dark Mode". | No. The app sets it through a task. | `set_display` |

| Lock state | `mobster devices lock-probe` | `/api/status` | `unlock_status`, `unlock` |
| Device status | `mobster doctor`, `mobster devices status` | `/api/status`, `/api/access` | `status`, `device_status` |
| Use an iPhone over Wi-Fi | `mobster wifi on`, `mobster wifi off`, `mobster wifi probe`, `mobster wifi status` | `/api/wireless` | No. Pairing a phone is the person's decision. |
| Set up an iPhone | `mobster setup` | `/api/setup` | No. Setup needs the person at the phone and the Mac. |
| Sign the helper without Xcode (paid team) | `mobster signing apply`, `mobster signing card`, `mobster signing export`, `mobster signing import`, `mobster signing resolve`, `mobster signing status` | `/api/setup` | No. It writes to the person's Apple team, so the person approves each request. |

- **Type text and sign-in codes.** mobster phone password types a password privately; other text goes through tasks.
- **Clipboard.** Reading the clipboard is for the person only, because it may hold a password.
- **Lock state.** Mobster never unlocks a phone or enters a passcode: unlock only tells the agent to ask the person.
