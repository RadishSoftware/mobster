## Set up

### `mobster doctor`

Check everything a task needs and print how to fix what is missing. Without `--fix` it changes nothing. Keys are shown masked: their first characters and last four.

`--fix` does the fix each finding carries, then checks again and prints what it did and what it could not do. It starts Mobster's helper, or refreshes one that expired, on its own, and leaves it to Mobster for Mac when that is running. It names a program that holds a port, or a service that doesn't answer, and asks before it stops it. It hands over to `mobster login` and `mobster setup` for what needs your answers. It never enters a passcode, runs sudo or downloads a runtime. Without a terminal, or with `--json`, it skips every question and says which.

**Options**

<ResponseField name={"--wda-url"} type={"URL"} default={"http://127.0.0.1:8100"}>
the phone's address, for a phone you set up by hand (default: http://127.0.0.1:8100) \[env: MOBSTER_WDA_URL\]
</ResponseField>

<ResponseField name={"--device"} type={"NAME"} default={"your iPhone"}>
the iPhone or simulator to use: an id, UDID or name from `mobster devices` (default: your iPhone)
</ResponseField>

<ResponseField name={"--env-file"} type={"PATH"}>
load KEY=VALUE lines (ANTHROPIC_API_KEY, OPENAI_API_KEY, ...); variables already set win \[env: MOBSTER_ENV_FILE\]
</ResponseField>

<ResponseField name={"--fix"} type={"flag"} default={"off"}>
do the fix each finding carries, then check again
</ResponseField>

<ResponseField name={"--json"} type={"flag"} default={"off"}>
print the checks as JSON
</ResponseField>

<ResponseField name={"--simulator"} type={"flag"} default={"off"}>
skip the USB iPhone and Xcode checks (a simulator's phone)
</ResponseField>

```text
exit codes: 0 ready for tasks (warnings allowed), 1 at least one problem

examples:
  mobster doctor
  mobster doctor --fix
```

**Options**

<ResponseField name={"--team"} type={"ID"}>

<ResponseField name={"--json"} type={"flag"} default={"off"}>


### `mobster devices`

List every device Mobster can drive: USB iPhones (set up or newly plugged in), Mobster's simulators, and phone addresses from MOBSTER_WDA_DEVICES. Each shows its state: Ready, In use, Connected, Needs setup or Unplugged. Name one with `--device` on run, screen, doctor, serve, mcp and the terminal UI. It changes nothing.

`mobster devices lock-probe` reads whether an iPhone is locked or showing a system sheet (Face ID, a locked app, the App Store's side-button confirmation) the way a task's check does, and lists what the lock screen shows. It taps and types nothing.

`mobster devices status` reads a device's battery and thermal state, and whether this Mac is on battery. A value the device doesn't report is left out. Without `--device` it reads the only device, else the first iPhone set up.

**Arguments**

<ResponseField name={"lock-probe|status"} type={"lock-probe | status, optional"}>
lock-probe: the lock state and system sheets; status: battery and heat. Neither taps anything
</ResponseField>

**Options**

<ResponseField name={"--json"} type={"flag"} default={"off"}>
print the devices (or the probe, or the status) as JSON
</ResponseField>

<ResponseField name={"--wda-url"} type={"URL"} default={"$MOBSTER_WDA_URL, else http://127.0.0.1:8100"}>
lock-probe, status: the phone's address (default: `$MOBSTER_WDA_URL`, else http://127.0.0.1:8100)
</ResponseField>

<ResponseField name={"--device"} type={"NAME"}>
lock-probe, status: the device to read, by id, UDID or name
</ResponseField>

```text
examples:
  mobster devices
  mobster devices --json
  mobster devices lock-probe --device "Sam's iPhone"
  mobster devices status --device "Sam's iPhone"
  mobster run "Turn on Dark Mode" --execute --device "Sam's iPhone"
```

### `mobster login`

Save your Claude or OpenAI key for Mobster's agent, on this Mac. Mobster tests the key with one tiny request first, then saves it in Mobster's settings file, which only you can read. Mobster for Mac and every `mobster` command use it. The key is never shown: only its first characters and last four.

`mobster login <plan or provider>` saves a plan's key or sign-in (Kimi Code, Grok ...) or another provider's key. A ChatGPT, Claude or Google plan runs through your own Codex, Claude Code or Gemini CLI, which signs in itself: `mobster login codex` says how.

`mobster login status` shows which keys, plans and providers are saved.

**Arguments**

<ResponseField name={"status|PLAN|PROVIDER"} type={"status|PLAN|PROVIDER, optional"}>
status: show what is saved, masked; a plan or provider: kimi, zai, grok, openrouter, xai, custom ...; codex, claude or gemini: how that CLI signs in
</ResponseField>

**Options**

<ResponseField name={"--provider"} type={"anthropic | openai"}>
anthropic (Claude, the default) or openai
</ResponseField>

<ResponseField name={"--with-key"} type={"flag"} default={"off"}>
read the key from standard input (a pipe or a file, never a terminal)
</ResponseField>

<ResponseField name={"--skip-check"} type={"flag"} default={"off"}>
save it without testing it (no network)
</ResponseField>

<ResponseField name={"--json"} type={"flag"} default={"off"}>
print the result as JSON
</ResponseField>

<ResponseField name={"--model"} type={"ID"}>
a plan or provider: the model Mobster's agent uses there
</ResponseField>

<ResponseField name={"--base-url"} type={"URL"}>
custom, ollama or lmstudio: the endpoint's base URL, such as http://127.0.0.1:11434/v1
</ResponseField>

```text
exit codes: 0 saved (or status shown), 1 the key or the sign-in didn't work, 2 usage,
            130 ctrl+c

examples:
  mobster login
  mobster login --provider openai
  mobster login --provider anthropic --with-key < key.txt
  mobster login kimi
  mobster login status
```

### `mobster logout`

Remove a saved key from this Mac: from Mobster's settings file, which Mobster for Mac uses too. A key set in your shell or an `--env-file` stays where it is.

`mobster logout <plan or provider>` forgets that plan's or provider's key or sign-in.

**Arguments**

<ResponseField name={"PLAN|PROVIDER"} type={"PLAN|PROVIDER, optional"}>
forget a plan's or provider's key or sign-in, instead of removing a key
</ResponseField>

**Options**

<ResponseField name={"--provider"} type={"anthropic | openai"} default={"the one Mobster's agent uses"}>
which key to remove (default: the one Mobster's agent uses)
</ResponseField>

```text
examples:
  mobster logout
  mobster logout --provider openai
  mobster logout kimi
```

### `mobster wifi`

Turn on Wi-Fi use for an iPhone you set up with a cable once, see how each phone is connected, and check the encrypted link between this Mac and the phone.

```text
examples:
  mobster wifi status
  mobster wifi on --device "Sam's iPhone"
  mobster wifi probe --device "Sam's iPhone"
```

| Command | What it does |
|---|---|
| [`mobster wifi status`](#mobster-wifi-status) | show how each iPhone is connected, and whether Wi-Fi is on for it |
| [`mobster wifi on`](#mobster-wifi-on) | let an iPhone be used over Wi-Fi (plug it in first) |
| [`mobster wifi off`](#mobster-wifi-off) | use an iPhone only with the cable again |
| [`mobster wifi probe`](#mobster-wifi-probe) | check the encrypted Wi-Fi link to an unplugged iPhone, step by step |

<a id="mobster-wifi-status"></a>

**`mobster wifi status`**

Show each iPhone set up here: on the cable, on Wi-Fi, or not reachable, and whether Wi-Fi is on for it. Reads only; changes nothing.

**Options**

<ResponseField name={"--json"} type={"flag"} default={"off"}>
print one JSON object
</ResponseField>

<a id="mobster-wifi-on"></a>

**`mobster wifi on`**

Let Mobster reach an iPhone over Wi-Fi when it's unplugged, through the encrypted link between this Mac and the phone. The iPhone must be plugged in and trust this Mac; this is the same switch as Connect via network in Xcode.

**Options**

<ResponseField name={"--device"} type={"NAME"} default={"your iPhone"}>
the iPhone: an id, UDID or name from `mobster devices` (default: your iPhone)
</ResponseField>

<ResponseField name={"--json"} type={"flag"} default={"off"}>
print one JSON object
</ResponseField>

```text
exit codes: 0 on, 1 it couldn't be turned on, 2 usage, 3 no such iPhone
```

<a id="mobster-wifi-off"></a>

**`mobster wifi off`**

Stop using an iPhone over Wi-Fi. When Mobster turned on the iPhone's own switch (Connect via network), it turns that off too, over the cable. When it can't, or Xcode turned the switch on, it says what to do.

**Options**

<ResponseField name={"--device"} type={"NAME"} default={"your iPhone"}>
the iPhone: an id, UDID or name from `mobster devices` (default: your iPhone)
</ResponseField>

<ResponseField name={"--json"} type={"flag"} default={"off"}>
print one JSON object
</ResponseField>

```text
exit codes: 0 off, 1 it failed or the iPhone's own switch is still on (plug it in and run this again), 2 usage, 3 no such iPhone
```

<a id="mobster-wifi-probe"></a>

**`mobster wifi probe`**

Check an unplugged iPhone over Wi-Fi: what Xcode's device service reports, the encrypted tunnel, WebDriverAgent on the tunnel through this Mac's relay, and that the phone's Wi-Fi address does not answer on 8100 or 9100. It binds only 127.0.0.1 and changes nothing on the phone (with `--start`, it launches Mobster's helper on it for the probe, then stops it).

**Options**

<ResponseField name={"--device"} type={"NAME"} default={"your iPhone"}>
the iPhone: an id, UDID or name from `mobster devices` (default: your iPhone)
</ResponseField>

<ResponseField name={"--start"} type={"flag"} default={"off"}>
launch Mobster's helper over Wi-Fi for the probe when it isn't running (quit the Mac app first)
</ResponseField>

<ResponseField name={"--json"} type={"flag"} default={"off"}>
print one JSON object
</ResponseField>

```text
exit codes: 0 every check passed, 1 a check failed, 2 usage, 3 couldn't run
```

### `mobster update`

Check for a newer standalone CLI on PyPI, or a frozen CLI archive on GitHub. Upgrade with the installer you used: pip, uv, npm or the frozen archive. This command installs nothing. A copy owned by Mobster for Mac uses the app's updater. Mobster checks once a day after interactive commands; MOBSTER_NO_UPDATE_CHECK=1 turns off the daily check. An explicit mobster update still checks.

**Options**

<ResponseField name={"--check"} type={"flag"} default={"off"}>
only say whether a new release is out
</ResponseField>

```text
examples:
  mobster update
  mobster update --check
```

### `mobster audit`

Check a Team plan audit export offline: the hash chain, the signed head of the API's export, and with `--keys` every Mac's signature. Nothing leaves this Mac.

```text
examples:
  mobster audit verify audit.jsonl
  mobster audit verify audit.jsonl --keys keys.json
  mobster audit verify export.json
```

| Command | What it does |
|---|---|
| [`mobster audit verify`](#mobster-audit-verify) | check an audit export's hash chain and signatures |

<a id="mobster-audit-verify"></a>

**`mobster audit verify`**

Check an audit export, offline. It follows the hash chain entry by entry and says which entry first fails: a gap, an entry out of order, or one that was changed. For the JSON Lines export from the API it also checks the signed head against Mobster's license key, which pins where the export starts, where it ends and how many entries it holds, so a cut-off start or end is caught too. With `--keys` it checks each Mac entry's signature against that Mac's key. The relay's own entries are unsigned.

Get the Macs' keys from the Macs themselves, not from the export, so the relay can't vouch for itself. Nothing leaves this Mac.

**Arguments**

<ResponseField name={"FILE"} type={"FILE"} required>
the audit export: JSON Lines from the API, or JSON from the console
</ResponseField>

**Options**

<ResponseField name={"--key"} type={"FILE"} default={"the key built into Mobster"}>
the license public key, as a PEM, for a JSON Lines export's signed head (default: the key built into Mobster)
</ResponseField>

<ResponseField name={"--keys"} type={"FILE"}>
a JSON file of \{"\<mac id\>": "\<base64url Ed25519 public key\>"\}; checks every Mac entry's signature
</ResponseField>

<ResponseField name={"--json"} type={"flag"} default={"off"}>
print the result as one JSON object
</ResponseField>

```text
examples:
  mobster audit verify audit.jsonl
  mobster audit verify audit.jsonl --keys keys.json
  mobster audit verify export.json

exit codes: 0 every entry checked out, 1 something didn't check out, 2 a file couldn't be read
```

### `mobster signing`

Put Mobster's helper on an iPhone without Xcode, for a paid Apple Developer team. With your own App Store Connect key, `card` reads your team and prints the three requests Mobster would send to Apple (register your iPhone, create a development certificate, create a development profile), and `apply` sends them after you approve their digest, signs the helper on this Mac and installs it with pymobiledevice3. Off unless MOBSTER_EXPERIMENTAL_NO_XCODE=1.

```text
examples:
  mobster signing card
  mobster signing apply --approve <digest>
  mobster signing export helper.tgz
  mobster signing import helper.tgz --team ABCDE12345
```

| Command | What it does |
|---|---|
| [`mobster signing status`](#mobster-signing-status) | say whether signing without Xcode is on, what it has and what it waits for |
| [`mobster signing card`](#mobster-signing-card) | read your team and print the requests Mobster would send to Apple, with a digest |
| [`mobster signing apply`](#mobster-signing-apply) | send the card you approved, sign the helper on this Mac and install it |
| [`mobster signing resolve`](#mobster-signing-resolve) | say whether a change whose answer Mobster never saw was made |
| [`mobster signing export`](#mobster-signing-export) | write the signed helper and its profile to a file other Macs can install |
| [`mobster signing import`](#mobster-signing-import) | install a helper that another Mac signed |
