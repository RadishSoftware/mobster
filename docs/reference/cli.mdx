## `mobster login`

Save your Claude or OpenAI key for Mobster's agent, on this Mac. Mobster tests the key with one tiny request first, then saves it in Mobster's settings file, which only you can read. Mobster for Mac and every `mobster` command use it. The key is never shown: only its first characters and last four.

`mobster login status` shows which keys are saved.

**Arguments**

</ResponseField>

**Options**

<ResponseField name={"--with-key"} type={"flag"} default={"off"}>

<ResponseField name={"--skip-check"} type={"flag"} default={"off"}>

<ResponseField name={"--json"} type={"flag"} default={"off"}>

## `mobster run`

Run one task on your iPhone and print each step. On a terminal each step prints as a line; piped, or with `--json`, every event prints as one JSON object per line, and the last is the result.

Which agent runs it (`--engine` auto): Mobster's agent (Smart) on your Claude or OpenAI key, or Quick mode (Fast) when TYPESAFE_API_KEY is set. Smart asks before it sends, buys, posts or deletes: on a terminal you answer y or n; with `--json` or a pipe the answer is no, and the run ends as declined. Fast never asks: with `--execute` it can send, buy, post or delete without a prompt, so preview without `--execute` first.

ctrl+c stops at the next safe point (twice to force).

**Arguments**

<ResponseField name={"TASK"} type={"TASK"} required>
what to do, in plain words
</ResponseField>

**Options**

<ResponseField name={"--wda-url"} type={"URL"} default={"http://127.0.0.1:8100"}>
the phone's address, for a phone you set up by hand (default: http://127.0.0.1:8100) \[env: MOBSTER_WDA_URL\]
</ResponseField>

<ResponseField name={"--device"} type={"NAME"} default={"your iPhone"}>
the iPhone or simulator to use: an id, UDID or name from `mobster devices` (default: your iPhone)
</ResponseField>

<ResponseField name={"--env-file"} type={"PATH"}>
load KEY=VALUE lines (ANTHROPIC_API_KEY, OPENAI_API_KEY, TYPESAFE_API_KEY, ...); variables already set win \[env: MOBSTER_ENV_FILE\]
</ResponseField>

<ResponseField name={"--execute"} type={"flag"} default={"off"}>
act on the phone (Fast without it: preview one decision)
</ResponseField>

<ResponseField name={"--engine"} type={"auto | smart | fast"} default={"auto"}>
smart (Mobster's agent), fast (Quick mode), or auto: fast when TYPESAFE_API_KEY is set, else smart (default: auto) \[env: MOBSTER_DEFAULT_ENGINE\]
</ResponseField>

<ResponseField name={"--demo"} type={"flag"} default={"off"}>
a scripted phone and policy: no iPhone, no keys, no model calls
</ResponseField>

<ResponseField name={"--helper"} type={"flag"} default={"off"}>
Fast: use the helper model for typed text, answers and recovery (TEXT_MODEL)
</ResponseField>

<ResponseField name={"--json"} type={"flag"} default={"off"}>
print raw JSON events, even on a terminal
</ResponseField>

<ResponseField name={"--max-steps"} type={"N"} default={"30"}>
stop after N steps (default: 30)
</ResponseField>

<ResponseField name={"--max-seconds"} type={"S"} default={"120"}>
stop after S seconds (default: 120; Smart: 300)
</ResponseField>

<ResponseField name={"--spend-cap-usd"} type={"USD"}>
stop before further model calls once this task has cost USD
</ResponseField>

<ResponseField name={"--expected-text"} type={"TEXT"}>
Fast: finish as soon as TEXT is visible on the screen
</ResponseField>

<ResponseField name={"--allow-app"} type={"BUNDLE_ID"} post={["repeatable"]}>
Fast: let the agent switch to this app; repeat for several. Without any `--allow-app`, app switching is never offered
</ResponseField>

`--wda-url` and `--device` can't be used together.

```text
exit codes: 0 done (or previewed), 1 the task didn't finish, 2 usage error,
            3 couldn't run (no phone answered, no key), 130 stopped with ctrl+c

examples:
  mobster run "Turn on Dark Mode" --execute
  mobster run "What's my battery level?" --execute --json
  mobster run "Turn on Dark Mode" --demo          a scripted phone: no iPhone, no keys
  mobster run "Open Search" --engine fast          preview Quick mode's first decision
```

Mobster installs and launches the app, runs the steps (Smart, on your OpenAI or Anthropic key) or none (a launch-only check), and decides the verdict from your expectations on the accessibility tree, never from a model. Each run writes a report with the frames that prove it.

**Arguments**

<ResponseField name={"STEP"} type={"STEP, zero or more"}>
one step of the flow in plain English; none means a launch-only check
</ResponseField>

**Options**

<ResponseField name={"--check"} type={"FILE"}>
run a saved check (.yaml or .json); not combined with steps or expectations
</ResponseField>

<ResponseField name={"--app"} type={"PATH"}>
the .app built for the iOS Simulator; it is installed before the run
</ResponseField>

<ResponseField name={"--bundle"} type={"ID"} default={"read from --app"}>
the app's bundle ID (default: read from `--app`)
</ResponseField>

<ResponseField name={"--device"} type={"NAME"} default={"iPhone 17 Pro, else the newest iPhone"}>
a device from `mobster devices` (its id, UDID or name), or the simulator device type (default: iPhone 17 Pro, else the newest iPhone)

### `mobster wifi probe`
