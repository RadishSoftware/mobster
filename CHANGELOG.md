# Changelog

All notable changes to Mobster CLI are listed here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning](https://semver.org/). Before 1.0, a minor version can change the command line or the API.

## Unreleased

### Fixed

- Generated app assemblies keep helper builds and runtime data outside the generated source tree.

- Your timed post no longer shows **Missed its time** when its profile's pace or posting window holds it more than 2 hours within its day. It goes out when both allow it, on its own day. If they would hold it to a later day, it misses its time. If your post misses its time, the note gives the reason: Mobster not running, a pause on its profile, a wait for your client's approval, or its profile's pace or posting window holding it past its day. **Run again** on a missed post now drops its old time. It goes once its queue runs and its profile's pace and window allow, even on a later day. If that run does not post, press **Run again** to try again. Before this fix, the queue's next check marked it missed again.

- Mobster adds text at the end of a field without emptying it first. If the field reads back differently, Mobster keeps the text and tells the agent what differs. A formatting change no longer triggers a rewrite that can leave the field empty.
- Keep screen signatures in the standalone engine boundary and include the frozen heldout task manifest.
- CLI tests use local fixtures; app packaging and service parity checks remain in the app repository.

- Standalone installs include the Wi-Fi pairing and packet-capture helper sources; frozen builds include every Swift helper.
- Update checks use PyPI for Python installs and CLI archives for frozen installs. App-owned copies use the Mac app updater.
- Generated CI jobs run the standalone CLI through uv. Runner checks require a Mac app account only for app-owned copies.

- Failed permission-store writes leave the active grants unchanged.
- Simulator leases close even when release callbacks fail, and simulator listings use one lease observation per row.
- Verification suites drain refused checks without recursive calls.
- Recent terminal-thread addresses use atomic file replacement.

### Maintenance

- Publish `mobster-cli` through a checked GitHub release workflow and provide `@radishsoftware/mobster` as a small uv launcher.

- Remove unused attach adapters and Android recording scaffolding; retain the existing app scorer and Android logs.
- Remove retired engine-export and app-only packaging/CI code from the standalone CLI.

### Added

- When no run is active, the canvas offers **Pause** or **Resume** for a published workflow's schedule, notification or app trigger, even with saved or unsaved edits. Saved draft changes can show **Changes not published** or **Proven, not published**.
- A workflow's canvas panel lists up to three runs under **Recent runs**. A one-task workflow's run opens from there while Mobster still has it on this Mac.
- Pause a workflow that starts by itself from its row on the Workflows page, whether a schedule, a notification or an app starts it. A paused row says **Paused**, and **Resume** turns it back on.
- Mobster for Mac ships `LICENSE` and `THIRD_PARTY_NOTICES.txt` in `Contents/Resources`: the licence texts of the frozen agent's Python packages and CPython, the dashboard's npm packages, the app's Rust crates and the iPhone tools. `python3 scripts/gen_app_notices.py` writes the file and `--check` fails when it is stale.
- The `ios-testing` skill teaches the loop from a verified flow to a saved check to `run_tests` on every pull request, adds a `references/agents.md` with the one-line install for Cursor, Codex, Windsurf and Xcode's agents, and a new docs page, [Mobster in Cursor, Codex, Windsurf and Xcode](https://docs.mobster.dev/agents/editors).
- Long-task reports distinguish requested outcomes, recorded values and confirmed action receipts across pickup. Memory can target a saved workflow or a saved profile and workflow together; pinned facts stay within that scope.

- `mobster doctor --fix` does the fix each finding carries, checks again, and prints what it did and what it couldn't. It starts Mobster's helper on your iPhone, or refreshes one whose 7-day signature ran out, on its own. It names the program that holds the helper's port, or Mobster's service when it stops answering, and asks before it stops either. It hands over to `mobster login` and `mobster setup` for what needs your answers. Without a terminal, or with `--json`, it skips every question and says which. It leaves the helper to Mobster for Mac or `mobster serve` when one runs, and never enters a passcode, runs `sudo` or downloads a runtime.
- `mobster doctor` also checks that this Mac has a network, that nothing else holds the helper's port, and whether Mobster's service answers.
- Workflow webhooks accept a signed versioned event ID, occurrence time and typed inputs. Mobster durably consumes each ID before dispatch and refuses duplicate, changed, expired or overlapping events.
- Experimental: `mobster history --to-eval ID` keeps a finished task as a regression task in your evals, and `python -m mobile_agent.bench evals` replays every one offline with no phone, no network and no model. It needs the task's tape (`MOBSTER_EXPERIMENTAL_TRACES=1`).
- Experimental: with `MOBSTER_EXPERIMENTAL_AUDIT=1`, `audit: ax-device` in a check runs Apple's own accessibility audit on a real iPhone (contrast, hit regions, missing descriptions, clipped text, Dynamic Type) with no model. A simulator has no such service and keeps the tree audit ([Accessibility audit](https://docs.mobster.dev/accessibility#apples-audit-on-a-real-iphone)).
- Experimental: with `MOBSTER_EXPERIMENTAL_SETTLE=1`, Mobster learns how long each app's transitions take to settle and, for a step the next read verifies, waits that long, reads once and goes on, instead of reading until two reads agree. Anything unexpected falls back to the normal reads. `python -m mobile_agent.settle.replay` projects the saving from a recorded `frameclock.jsonl`. On 276 recorded settles it cut accessibility reads per settle from 3.18 to 2.24 and left the settle time at 805 ms (808 ms before).
- Experimental: with `MOBSTER_EXPERIMENTAL_COMPILED_READ=1`, `read_screen` reads a screen with code and no model call when it has the shape of one the model already read, the agent's prompt sends what changed on the screen since a reference screen, and a saved program is offered only for the app version it was learned on. A miss goes to the model, and the answer's `compiled` counts both ([Configuration](https://docs.mobster.dev/configuration)).
- Experimental: with `MOBSTER_EXPERIMENTAL_SOUND=1`, `expect: [{sound: sent}]` passes when a real iPhone plays a sound you recorded once under `.mobster/sounds`. It is matched in code from a short spectral fingerprint, with no model ([Checks](https://docs.mobster.dev/checks#sounds)).
- Experimental: with `MOBSTER_EXPERIMENTAL_CORPUS=1`, `mobster corpus on` shows what Mobster would keep and, if you say yes, writes one private record per step of each finished task on this Mac: control roles, hashed labels and the action, never screenshots or typed text. `mobster corpus stats` counts them and `mobster corpus export --out FILE` writes them for you to read. Nothing is uploaded.
- Mac projects can save reviewed test checks from a task goal or finished run, record a path, and run strict checks with durable request IDs. Local project owners can approve an immutable revision of saved checks, a prebuilt simulator app, and a managed simulator for a later CI integration. A network stub's body file and a snapshot check's baselines are part of the revision, a stub's file must be inside the project, and a CI suite never records a baseline. A suite checks these files before each check and after its last one; when one changed, the suite fails and Mobster exports none of its results. A file changed and changed back between two of those checks isn't noticed.
- Test suites pin admitted inputs and preserve stopped or uncertain outcomes. Local commands can run ordered simulator scenarios, inspect and export completion-bound evidence, compare exact suites, and try a bounded paired reproducer.
- Checks can assert scalar app state through an explicitly enrolled simulator fixture. Verification journals device effects before dispatch, preserves uncertain outcomes, and keeps healed replay paths separate until reviewed.
- **Edit** on your own server's page changes its name and its URL or command in place. Before, a typo in the address meant **Remove** and add it again. A URL on another host never gets the old server's token or OAuth sign-in, and a new command must answer MCP before it's saved. A directory or plugin connector keeps its address.
- Experimental: with `MOBSTER_QUEUE_PREFLIGHT=1`, the content queue looks at the iPhone before it sends. A locked iPhone, or one whose lock Mobster can't read, keeps a due post **Ready** until you unlock it, and Setup gets a row, **Let Mobster add to Photos**, that makes iOS ask on the iPhone (you answer there; Mobster never presses it). **Start queue** refuses an iPhone without Photos access, so no file waits 60 seconds for an answer nobody gives, and warns when Low Power Mode would lock the iPhone after 30 seconds. A scheduled workflow on such an iPhone gets a `phone_low_power` event. Approve the batch answers a Post card only after Mobster saw the post's media in the composer, and Instagram and TikTok's limited-photos notice ends the post as **Didn't post**. The chunked save names its file with its extension, which PhotoKit needed to take it under Limit Access in an iOS 26.4 simulator. Each iPhone rebuilds Mobster's helper once when the flag is turned on ([Content queue](https://docs.mobster.dev/content-queue#check-the-iphone-first)).
- `mobster mcp install copilot-cli` adds Mobster to GitHub Copilot CLI (`~/.copilot/mcp-config.json`, or `.github/mcp.json` with `--project`). `copilot` now names Copilot CLI, not VS Code. Windsurf, Codex CLI, opencode, Gemini CLI and Copilot CLI each have a page under [Add Mobster to your agent](https://docs.mobster.dev/agents), and `packaging/listings/` holds the MCP directory submissions.
- You can score existing benchmark and paired development evidence offline, with planned and graded denominators kept separate.
- Experimental: with `MOBSTER_EXPERIMENTAL_TRACES=1`, a task that didn't finish says why in one sentence that names the step: ran out of steps, gave up, called it done too soon, hit a prompt, lost the app, opened the wrong one, got stuck or hit an error. `mobster history` prints it, and a failed check's pull request comment ends with it.
- Experimental: `MOBSTER_EXPERIMENTAL_TRACES=1` records each task's trace as it runs, and `mobster export ID --trace` saves it as a zip you can attach to a bug report. Keys, codes and passwords are masked in it. Nothing is uploaded.
- Experimental: with `MOBSTER_EXPERIMENTAL_INTENTS=1`, Mobster reads the URL schemes and associated domains of a simulator's apps as discovered links, opens an app's link before tapping when a check names one app (`mobster intents harvest` fills the atlas; link-first steps and saved model calls appear in the reports), and builds x-callback-url return addresses. Discovered links are never marked verified, and every link still goes through the same ask rule ([Deep links](https://docs.mobster.dev/deep-links#deterministic-path-first-experimental)).
- A project can say where Mobster asks first. `.mobster/policy.yaml` names a profile, an app and a kind of act, says `ask` or `allow`, and can carry a time window and a daily cap. The policy only adds questions: the stricter of it and your permission mode wins, and a file with a mistake asks before every act. Off until `MOBSTER_POLICY=on`.
- `mobster run --dry-run` and `"dryRun": true` on `POST /api/runs` print the apps a task would open, the acts it would ask about and its estimated cost, and send nothing to your iPhone.
- Every approval for a step carries one sentence that says what Mobster will do and why it asks, in the terminal and in `phone_task_status`.
- Experimental: with `MOBSTER_EXPERIMENTAL_SYSTEM_SURFACES=1`, a check's `surfaces` block drives and reads what an app puts outside its window, on a simulator: an App Intent through a shortcut or Siri, a Home Screen widget (it adds it from the gallery), a Live Activity on the Lock Screen or in the Dynamic Island, Control Center, an App Clip opened by its invocation URL, Spotlight results and the share sheet. Each surface is read from the accessibility tree with the check's own assertions. A real iPhone refuses them, and an App Clip card opened by NFC, QR code, Safari banner or Maps has no simulator path ([System surfaces](https://docs.mobster.dev/checks#system-surfaces)).
- Setup gets a row, **Let Mobster add to Photos**, with the flag on: **Allow** makes iOS ask on the iPhone, and you answer there. Mobster never presses that button, and the row never holds the rest of Setup back.
- `python -m mobile_agent.bench.tape_replay` replays a trace bundle, and `--steps` lists each recorded action as the same or the one a change acts differently on. A recorded failure replays in under 4 s with no phone, no network and no model.
- A task you type on Home that says when it repeats ("every Monday at 9am", "daily") offers Make this repeat: a new workflow drafted from your words, with that schedule.
- A step that taps or types into an element records where that element sits in the step's frame (`focus`), and an approval's screen carries it in pixels, so a client page can ring what is being approved. It is left out when unknown, and never guessed.
- A queue post can be a draft: a caption and a profile with no media yet. It says "Add photos", never goes out as it is, and becomes a normal post once it has 1 to 10 files. A task started with `extras.queueDraft = {queue, profile}` leaves its text result as a draft there.
- `POST /api/runs/{id}/send` sends a finished result to a saved destination, and `POST /api/runs/{id}/issue` files it as an issue in a connected GitHub, Linear or Jira. Both refuse with a reason when nothing suitable is saved, and an issue whose answer never came is never sent again.
- A check's `dialogs:` block answers iOS's own screens with no model: `permissions` (location, Photos, notifications, tracking and the other permission alerts), `paste`, `sign_in_with_apple`, `biometric` (`match`, `nonmatch` or `cancel`) and `purchase`. Smart's steps and a replay both use it, and a replay that meets a dialog it hasn't seen answers it instead of failing. A fixture can hold the same block. Each answer is a `system_dialog` event in `events.jsonl`, and a replay that meets a dialog `dialogs` won't answer ends `couldnt_run`, class `system_dialog`. Only iOS's own dialogs are answered, on a simulator and an iPhone: an alert only while WebDriverAgent reports SpringBoard in front, or the Apple process for its own kind (StoreKit for a purchase alert, AuthKit for a Sign in with Apple alert, CoreAuthUI for a Face ID alert), and none of its lines is on the app's own screen; a sheet only while its Apple process is in front and the screen read is that process's own. A web page in Safari's process, an unknown front and the app's own alerts and screens get no answer, and the same dialog twice in a row in one run stops the check, in a replay or in Smart's steps. An Apple Account prompt, a dialog with a password field (when the screen read is Apple's own) and Trust This Computer outrank every permission alert and are never answered; an app's own alert with the same words stops the check too.
- `conditions.biometric: enrolled|not_enrolled` sets Face ID enrollment on the simulator for the run and puts it back.
- A check can end with `snapshot: NAME` in `expect`: Mobster compares the final screen to a baseline in `.mobster/snapshots/` for the device, appearance, text size and locale, with a 2 px blur and a per-pixel tolerance so antialiasing never fails, masks for dynamic regions (`id`, `label` or `rect`) and a `threshold` (default 0.1 % of pixels). A missing baseline is recorded and ends `needs_review`. `mobster test --update-snapshots [--check NAME]` writes baselines, `mobster test snapshots [stale|orphaned]` lists them, and the run folder, `results.json`, the report and `junit.xml` carry the baseline, current and diff images. `appearance`, `content_size` and `locale` in `conditions` may be lists, which run the check once for each combination.
- Every step of a check carries its own proof. `result.json` gains `step_proof` (and `results.json` `stepProof`): a one-line cause for a run that didn't pass, on the app's side, the check's or the environment's; the frame and screen read the verdict used; and per step the app's log lines and HTTP requests (method, host, status, duration and bytes, never paths or bodies) in that step's span. The run report folds them under each step, the suite report links each step's span in the `--video` recording, the pull request comment quotes the failing step's requests and last log lines, `run_tests` over MCP returns `failures[]` with the cause, and JUnit `<system-out>` carries the failing step. No model call.
- Every check run on a simulator now measures cold launch to the first stable screen, the app's peak and p95 resident memory, and hangs of 250 ms or longer, into `perf` in `results.json`, the HTML report, the PR comment and JUnit. `budget.launch_ms`, `budget.memory_mb` and `budget.hangs` fail a run that goes over with class `budget_exceeded`, and a limit on a number the run couldn't take ends `needs_review` with class `budget_unmeasured`. `mobster test --history` shows the last run's numbers, marked `↑` when they are 20% over the median of the last 10 passes. First frame and dropped frames are not measured on a simulator, and an iPhone run takes no memory sample.
- `mobster test repro crash.ips` turns a crash report into a check and runs it on a simulator with the screen recorded. It reads a `.ips`, a TestFlight or Xcode crash log, a Sentry event or a brief, and answers reproduced, crashed a different way, couldn't reproduce (with the steps tried) or couldn't run. The `repro_crash` MCP tool does the same for your coding agent; after the fix, the check passes once the app stops crashing. Daybreak plants five crashes to try it on.
- The Mac app sends a finished result to a saved destination, or files it as an issue in a connected GitHub, Linear or Jira, from **Send to…** and **File as issue…** in the answer's **⋯**. Each opens under the result, and a line there says where it went.
- A Cursor and VS Code extension (`editors/vscode`, installed from a VSIX you build with `npm run package`): a side panel with the simulator your checks run on, live; your checks with run, a lens above each check file and above each SwiftUI view whose screen a check covers; the failure's reason, expectations and screen; healed steps to accept or keep failing; approvals; and test on save, which builds the app and runs the checks that cover what you changed since your last commit. It talks to Mobster for Mac's agent or `mobster serve`, never to a phone, and runs checks on simulators only.
- `mobster mcp install … --rules DIR` writes Mobster's rules for coding agents into DIR: a block in `AGENTS.md`, and `.cursor/rules/mobster.mdc` for Cursor. Run it again and nothing changes; `--remove --rules DIR` takes them out.
- `GET /api/tests/project`, `POST /api/tests/suites`, `GET /api/tests/suites/{id}`, `POST /api/tests/suites/{id}/stop` and `POST /api/tests/heals` on the local API: a project's checks, a suite on simulators, and its heals, for the editor extension.
- A project's page in the Mac app gains its testing sections, behind `MOBSTER_EXPERIMENTAL_TESTS_PAGE=1`: heals to review (each step before and after and its two frames, **Accept** and **Keep failing**), each check's flake score and run times on its row, its schedules with an on and off switch for this Mac, its deep links with each one's last check and **Check links**, its fixtures with **Apply** on a simulator, and its snapshots. **Run checks** gains a menu that picks a simulator, a plugged-in iPhone (with a plan, while no task holds it) and a tag. There's no separate Tests page: `/tests` still opens Projects.
- `GET` and `POST /api/tests/heals` list and settle heals, `GET /api/tests/heals/frame` reads a waiting heal's frame, `POST /api/tests/fixtures/apply` applies fixtures to a simulator, `POST /api/tests/schedules/switch` turns a schedule off or on for this Mac, and `GET /api/tests/snapshots` lists the screens that differ from their baseline (none until `snapshot:` assertions write them). `GET /api/tests/links` says each link's last check, and `POST /api/projects/{id}/runs` takes `{sims}` or `{device}`, and `{tags}` or `{links: true}`.
- Each MCP client gets its own simulator. A phone tool called with no `run_id` and no `device` leases one for that `mobster mcp` server, keeps it for 30 idle minutes, and, when none is free, answers at once with who holds each. Mobster boots another simulator only with 4 GB of memory free, and waits to boot while the Mac's load is at or above one task per core. `MOBSTER_MAX_SIMS` now defaults to 4 and `MOBSTER_MAX_LOAD` sets when the Mac counts as busy. `mobster sim list` shows the holder of each simulator, and `mobster sim release --all-mine` asks your agents to let go.
- `mobster test --xctest` (and `mobster test pr --xctest`) also builds your Xcode project once with `build-for-testing`, runs its XCTest and Swift Testing targets on a simulator beside the checks, and merges the `.xcresult` into the one report: an XCTest section in `index.html` and `results.json`, one `<testsuite>` per target in `junit.xml`, each test in `mobster test --history` with a flake score, one line per failed test with its file and line in the PR comment and the Slack message, and exit code 1 when a test fails. `--test-plan` and `--only-testing` choose what runs, and with `test pr` the changed test files choose the targets. Mobster doesn't retry a test or run tests on an iPhone. The Daybreak sample gains a `DaybreakTests` target.
- A Cursor and VS Code extension (`editors/vscode`, installed from a VSIX you build with `npm run package`): a side panel with the simulator your checks run on, live; your checks with run, a lens above each check file and above each SwiftUI view whose screen a check covers; the failure's reason, expectations and screen; healed steps to accept or keep failing; approvals; and test on save, which builds the app and runs the checks that cover what you changed since your last commit. It talks to Mobster for Mac's agent or `mobster serve`, never to a phone, and runs checks on simulators only.
- `mobster mcp install … --rules DIR` writes Mobster's rules for coding agents into DIR: a block in `AGENTS.md`, and `.cursor/rules/mobster.mdc` for Cursor. Run it again and nothing changes; `--remove --rules DIR` takes them out.
- `GET /api/tests/project`, `POST /api/tests/suites`, `GET /api/tests/suites/{id}`, `POST /api/tests/suites/{id}/stop` and `POST /api/tests/heals` on the local API: a project's checks, a suite on simulators, and its heals, for the editor extension.
- `conditions.network: offline | slow-3g | lte | flaky` limits a simulator app's connection, and `stubs:` answers named requests with fixed responses, so offline screens, spinners, retries and empty states can be checked. A local proxy per run and a small library that points the app's `URLSession` at it do the work: no root, nothing left on your Mac, and a real iPhone refuses both. It doesn't reach Reachability, non-`URLSession` stacks or web views; `docs/testing.mdx` lists what it covers.
- `mobster account ci-token create|list|revoke` makes, lists and revokes CI tokens, and Settings › CI tokens in the console does the same. A token lasts 90 days unless you choose up to 365, is shown once, and stops at a runner's next run once revoked (the runner asks Mobster first; with no network, expiry stands). `mobster ci doctor` reports a revoked token.
- `mobster ci init --hosted` writes a workflow for GitHub's hosted `macos-15` runner, and `--host xcode-cloud|codemagic|bitrise|circleci` writes that service's file. A hosted job installs Mobster for Mac with Homebrew and signs in with `MOBSTER_CI_TOKEN`, a CI token that licenses simulator runs of `mobster ci run` and `mobster test` and never a phone. `mobster ci doctor` skips the rows that keep a Mac running and checks the token on a hosted runner. CI tokens stay off until Mobster turns them on.
- `expect:` takes `request`, `no_request` and `storage` on a simulator, behind `MOBSTER_EXPERIMENTAL_NETWORK=1`: a check can require `POST api.example.com/v1/cart` to have left the app, forbid any request to a tracker, or require a file or a SQLite query in the app's container to have changed. The report shows the matched request line or the storage diff with secrets masked. A real iPhone is refused; `docs/testing.mdx` lists the MITM steps as an unverified plan.
- `mobster test --a11y` (and `a11y: warn` or `a11y: strict` in a check) audits each screen a check visits. It adds three rules to the four it had: duplicate labels, labels that say nothing (`button`, `icon_close.png`, `ic_close`) and controls wholly off the screen. Findings are warnings by default and fail the check with `--a11y=strict`.
- `.mobster/a11y-baseline.json`, written by `mobster test --a11y --update-a11y-baseline`, keeps known findings from failing CI, so a run fails only on new ones. The JUnit file lists a warning as a passed case with its text and leaves baseline findings out; the HTML report counts new, warnings and baseline findings.
- `mobster test --locale de,ja,ar` runs every check once in each language. The app launches in that language and region, and the screens are read for truncated text, English text in a non-Latin language and a right-to-left layout that didn't mirror. Each language has its own result, JUnit suite entry and history.
- `mobster test --parallel` stops at what your Mac holds (one simulator per two cores and per 4 GB of memory) and says so. `MOBSTER_TEST_MAX_PARALLEL=N` sets the limit.
- `mobster test --history` shows each check's last 20 results per device with its pass rate, duration trend and flake score, and says which checks are flaky. The summary, `results.json` and the HTML report suggest quarantining them, and `--auto-quarantine` quarantines them for a run. The Mac app reads the same numbers from `GET /api/tests/history`.
- `.mobster/fixtures/NAME.yaml` names the state a check starts from: a reset, launch args and env, seed files copied into the app's container, a keychain reset, a pasteboard and sign-in steps. A check says `fixture: logged-in-cart`, and fixtures compose with `extends`.
- `mobster fixtures list` shows them, `mobster fixtures apply NAME --bundle ID` puts a simulator's app in one now, and `GET /api/tests/fixtures` lists them for the Mac app. On a real iPhone a fixture that resets, seeds files, resets the keychain or sets the pasteboard is refused before the phone is touched.
- `mobster env set|list|unset` keeps a project's test credentials in your Keychain, named in `.mobster/env.example` (names only, committed). A check writes `${NAME}` in `launch.args`, `launch.env`, `launch.url` and its steps; the run fills it in and masks every value in its log, events, result, report and step list. A name with no value, or not in `env.example`, ends the run as `couldnt_run` before a simulator starts, naming the variable. `GET`, `POST` and `DELETE /api/project/env` do the same for the Mac app, and never return a value.
- A saved task that belongs to a project (through its registered workflow-file binding) uses the project's secrets: `${NAME}` in its goal or steps is filled in for Mobster's agent when the task starts, and masked from the agent's first turn on. The task keeps `${NAME}` in its record. A missing value, a coding-agent engine, or a request through the plain API refuses the task at admission and names the variable.
- Device conditions gain `increase_contrast`, `route` (the device moves along 2 to 50 waypoints) and the `wifi_mode` and `cellular_mode` status bar settings.
- `mobster links list` shows a project's deep links from `.mobster/links.yaml`, the Expo config, the Xcode project (URL types and associated domains) and links a check opened successfully. `mobster links check` opens each on a simulator and records the screen it lands on: a pass when the screen shows the link's title, a fail with a screenshot when it doesn't.
- A step can say `open cart` for a link called cart. `GET /api/tests/links` lists them for the Mac app, and the app saves and removes the ones in `links.yaml`.
- `mobster expo dev` runs the Expo dev loop: it starts this project's Metro (or reuses it), builds and installs your dev client when the device has none, opens the app, and reloads it each time you save a source file. `--check` runs your saved checks on the device once the app is up, and ctrl+c stops the Metro it started.
- When Metro can't bundle the app, `mobster expo dev` and `mobster expo preview --expect` fail at once with Metro's error, the file and the line, instead of waiting out the timeout. A dev client's red error screen is read the same way.
- An app with `app.json` (an `expo` object) or an `app.config.*` file counts as an Expo project even before its packages are installed.
- The Mac app can start, check, reload and stop a project's dev server through `/api/tests/expo`.
- `mobster import maestro` converts Maestro flows into checks. A command Mobster can't run, such as `runScript`, becomes a step marked `TODO` that Smart fills on the check's first run, instead of refusing the whole flow, and a summary table counts what converted, what needs a first run and what is unsupported. An assertion Mobster can't judge still refuses the flow. Importing twice writes the same files and prints `unchanged`, and an edited check is kept without `--force`.
- `mobster testflight list` shows your app's TestFlight builds and which ones can be installed, and `mobster testflight install` installs one on your iPhone through the TestFlight app. `--build` picks a build. An expired or still-processing build is refused with the reason, and for an older build Mobster prints the taps instead of choosing one for you.
- `mobster testflight key add` keeps an App Store Connect API key for one project in your Keychain. It is never printed.
- The build and version you installed go in `results.json`, the JUnit properties and the HTML report of the next `mobster test --testflight` run.
- Mobster for Mac can list builds, install one and manage the key through the local API (`/api/tests/testflight/*`).

### Security

- Wi-Fi for iPhones (preview): setting up a new iPhone no longer turns on its Connect via network switch by itself. Mobster asks for each phone: **Use over Wi-Fi** in the Mac app, or `Use Sam's iPhone over Wi-Fi when it's unplugged? - Mobster's helper on the iPhone refuses a request with no `Host` header, as it already refused a web page's. Each iPhone's helper is built again once, as after any change to its patches.

- An unknown action outcome takes precedence over answer-extraction errors, so a missing answer never suggests repeating an action whose outcome is unknown.

### Security

- Mobster checks what an attached file is from its first bytes, so a program renamed `menu.pdf` is refused. Files move only to and from apps' own folders, over the cable: never the camera roll, never other apps' data. When the Mac app runs the server, only the app itself can put a file on the phone. A picture the agent sees carries none of the photo's details, so where a photo was taken stays on this Mac. A file dropped anywhere in the app that doesn't take it is refused, never opened in place of the app.
- Speech becomes text on this Mac. The microphone is on only while you talk, nothing is recorded or kept, and Mobster asks for the microphone and speech recognition the first time you tap the mic, never before. Voice never answers an approval: sending, buying, posting or deleting still needs your click or keypress.
- Mobster doesn't automate dating apps. - Tasks another agent starts over MCP can't start in Hinge or Bumble under their App Store bundle ids either.

## 0.2.0 - 2026-10-06

Mobster becomes a tool for checking iOS apps: your agent writes the screen, and `mobster verify` checks it and returns pass or fail with the frames that prove it.

### Added

- **`mobster verify`.** Checks an iOS app on a headless simulator: it installs your `.app`, launches it, optionally opens a deep link and runs steps, then decides the verdict from assertions on the accessibility tree (`text`, `no_text`, `visible`, `absent`, `value`, `count`), never from a model. Exit codes: 0 passed, 1 failed, 2 needs review, 3 couldn't run. Every run writes a folder with `result.json`, a self-contained `report.html`, the frames with an accessibility overlay, and its check as `check.yaml`. Checks can be YAML files (`--check`), flags (`--text`, `--visible`, `--expect` …) or MCP arguments. Steps run in Smart mode on your OpenAI or Anthropic key, capped by `--max-usd`.
- **`mobster mcp`.** An MCP server over stdio, tested with Claude Code; setups for Codex and Cursor. Key-less, the coding agent drives the app with `screen`, `tap`, `type_text`, `swipe`, `alert`, `open_url` and `relaunch`, and `verify_finish` returns the verdict; Mobster calls no model. With a key, `verify` runs the steps itself. Every call returns within 50 seconds, and long work continues under a `run_id`.
- **`mobster sim`.** Mobster creates, boots and reuses its own headless simulators (`Mobster · iPhone 17 Pro · iOS 26.4`), builds the pinned WebDriverAgent once per Xcode version, keeps it on 127.0.0.1, and resets the app between runs. `list`, `prepare`, `doctor`, `shutdown`, `erase`, `delete` and `prune`.
- **A standalone binary.** `curl -fsSL https://mobster.dev/install.sh | sh`, or `brew install radishsoftware/tap/mobster`, installs a signed build for Apple silicon that needs no Python. The script checks the download's SHA-256 and signature, installs into `~/.mobster`, links `~/.local/bin/mobster`, and never uses `sudo`. Homebrew installs the same build as a cask and needs no Command Line Tools.
- Docs: getting started with verify, checks, coding agents and simulators.
- **The terminal UI.** `mobster` opens it. You type a task and watch each step, with its target, confidence, timing and what the phone did. Approvals appear inline and take `y` or `n`, the phone's screen shows beside the transcript, and a status line shows the mode, models, spend and cap. It has slash commands (`/app`, `/model`, `/ask`, `/bypass`, `/cap`, `/preview`, `/format`, `/history`, `/resume`, `/device`, `/screen`, `/details`, `/clear`, `/help`), `@app` mentions, history with resume, and a summary printed on exit. It runs the same runtime as `mobster serve` and the Mac app.
- The phone view beside the transcript shows the real screenshot in terminals that draw images (kitty graphics protocol or sixel), and otherwise the screen as Mobster read it, with the element it is about to act on marked. Steps that did not act read calmly ("Looking for a way forward") and consecutive ones collapse into one line with a count.
- `mobster --demo`: the terminal UI with a scripted phone, for trying Mobster without an iPhone, keys or network.
- `mobster doctor`: checks Python, keys, the helper model, Xcode, libimobiledevice, the USB iPhone, the managed WebDriverAgent runner, WebDriverAgent, the lock screen and the device lock, and prints a fix for each problem. `--json` and `--simulator`.
- `mobster history`: lists the terminal UI's past tasks, and works while the UI is open.
- `mobster screen`: shows the phone's screen in the terminal, as real images in kitty, Ghostty, iTerm2 and WezTerm.
- `mobster version` and `mobster tui`.
- `mobster run` prints one readable line per step on a terminal. Piped, or with `--json`, it prints the same JSON lines as before.
- `$MOBSTER_ENV_FILE` sets the default `--env-file`, and `$MOBSTER_WDA_URL` the default `--wda-url`.
- Exit code 3 when no phone answers at the WebDriverAgent address.
- Docs: getting started, device setup, terminal UI, CLI reference, configuration, scripting and the API, architecture, benchmarks and troubleshooting. Also examples, a contributing guide, a security policy and issue forms.

### Changed

- The install script installs the standalone binary instead of installing through uv. If an earlier run installed Mobster with uv, the script stops and asks you to remove that copy first with `uv tool uninstall mobster-cli`.
- `mobster run` no longer requires `--wda-url`. It defaults to `$MOBSTER_WDA_URL`, else `http://127.0.0.1:8100`.
- `mobster --help` and every command's help were rewritten, with examples. The help is pinned by snapshot tests.
- The package depends on Textual for the terminal UI. The Mac app's bundled agent leaves it out.
- The terminal UI's header reads "Mobster CLI" in the text color. Violet stays for what needs you.
- Smart task steps name the row a sideways swipe crossed ("Swiped left on Buy oat milk") and what an icon button does ("Tapped More"). The one-line answer drops a leading "I" before a past-tense verb ("Added the reminder…"); the full answer and `data` stay as written.
- The API sends run frames and app icons with `Cache-Control: no-store`, so no copy of a phone screen outlives its task in a client's cache.

### Fixed

- One line in an env file that Mobster can't read (a space in a name, text that is not UTF-8) no longer stops it. The line is skipped and its number printed to stderr.
- Saving a key into an env file with a line that is not UTF-8 no longer fails with a codec error. The line is kept byte for byte.
- `POST /api/export` answers 403 `downloads_denied` when Mobster may not write to Downloads, instead of 408 "Request timed out".
- HTTPS calls failed certificate verification on a Python with no CA file of its own, such as the Mac app's bundled agent or a python.org install before its "Install Certificates" step. Mobster now verifies against macOS's bundle, `/etc/ssl/cert.pem`, when its Python has none. `SSL_CERT_FILE` and `SSL_CERT_DIR` still win, and `mobster version --json` reports the CA file and how many CAs it loaded.
- `mobster --wda-url URL run …` drove the default phone: an option given before the command was dropped, and so were `--env-file` and `--demo`. `--wda-url` and `--env-file` now reach the command from either side of its name, and `--demo`, `--resume` and `--app`, which only the terminal UI takes, are a usage error with another command.
- `mobster run --execute` on a WebDriverAgent other than port 8100, such as a simulator's on 8203, watched the USB iPhone's screen stream (9100) to tell when the screen had settled. It now watches the stream paired with its own port (8203 to 9203). A port with no pair, below 8100 (such as 8080) or above 64535, has no stream: the run settles by time, and the live view shows screenshots.
- Two processes could drive one phone by writing its address another way (`localhost` for `127.0.0.1`), or by running where `$TMPDIR` differs (ssh, cron). The device lock now names a phone by its host and port and lives in the data folder, and `mobster run` says when another process is using the phone. It also takes the lock that 0.1.0 takes, so a Mac app or CLI not yet updated and an updated one still keep off each other's phone.
- With only an OpenAI key, `mobster doctor` said ready although `mobster run` needs `TYPESAFE_API_KEY`, and `run` found out only after it had contacted the phone. Doctor now warns, and `run` checks the key first and says what it needs. The terminal UI names the Smart model, asks for the key the next task needs, and says that a preview needs a Jev key.
- The terminal UI removed every `@word` from a task, so "Follow @nasa in TikTok" reached the agent as "Follow in TikTok". Only an `@word` that names an app is removed now.
- `mobster --app` with an app installed on the phone but not in the catalog, or with a name no app has, was ignored without a word. It now chooses the installed app, or says there is no app by that name. When the phone's apps cannot be read yet, such as while WebDriverAgent starts, it looks again once the phone is ready, and a task waits for it meanwhile.
- The terminal UI and the Mac app's task composer picked Find My for "Find my boarding pass in Wallet" and Settings for "Message Sam about the camera settings". An app the task works in now comes first, a messaging verb's app beats an app named in the message, and "Find my boarding pass" names no app ("Find my iPhone" still means Find My). When the verb's object is an app, the task runs there: "Call an Uber" in Uber, "Message my Airbnb host" in Airbnb.
- The `@` list put bundle-ID matches first, so `@fa` and tab chose Safari. Apps whose name starts with the letters now come first.
- A Smart task that proved every part of the request (`completed`) read as a grey "Completed". It reads "Done", as a success, in the terminal UI and `mobster history`.
- `mobster run` exited with 1, not 3, when no phone answered in a way other than a refused connection, such as iproxy with no phone behind it, and an invalid `--max-steps`, `--max-seconds`, `--spend-cap-usd`, `--width` or `--wda-url` exited with 1 after contacting the phone. Both now exit as documented: 3 and 2.
- `mobster serve --help` promised a `$MOBSTER_WDA_URL` default that serve never read, and linked a page that does not exist. `serve --port 0` printed port 0 instead of the port it chose.
- `--env-file=~/keys.env` was read with the `~` as typed: the keys did not load, and the terminal UI saved its settings to a new `./~/keys.env`.
- A second terminal UI said "Cannot open the run journal; existing data was not reset". It now says another terminal UI is open.
- Quitting the terminal UI during a task printed "0 ms" for it. The summary now says how long it ran and that it stopped.
