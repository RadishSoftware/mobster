# Changelog

All notable changes to Mobster CLI are listed here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning](https://semver.org/). Before 1.0, a minor version can change the command line or the API.

## 0.3.0 - 2026-10-08

Mobster stops being one-shot: tasks belong to conversations that remember, Mobster's agent remembers what you tell it, takes files, listens in the Mac app and takes messages while it works, and `mobster test` runs your app's checks on simulators and your own iPhone. `mobster login` saves your key for the CLI and the Mac app, a finished task saves as a captioned GIF, and Siri, Shortcuts, Raycast and Alfred can start a task.

### Added

- Conversations. A task can belong to a conversation, and a follow-up uses what the earlier tasks found: ask Mobster's agent to find your last message from Kate Bell, then say "now reply to that". The rules you gave ("don't send anything yet") carry over word for word, and what earlier tasks read off the screen is treated as data, never as instructions. A conversation keeps its tasks' results after the 100-task history lets the tasks go, and survives restarts.
- A message sent while Mobster's agent works steers it at its next step; a message sent while it asks a question answers it. A message never approves anything: while an approval waits, it is refused.
- `mobster chat`: talk to Mobster's agent from Terminal, in a conversation, through the running Mobster app or `mobster serve`. With the Mac app open, approvals are answered there; with `mobster serve`, typing `y` approves the exact text shown. `--json` and runs without a terminal never answer an approval and exit 2.
- MCP's `phone_task` and `phone_task_status`: a coding agent hands a whole task to Mobster's agent in a conversation; the user approves sends, buys, posts and deletes in the Mobster app. These tasks never start in or open social or dating apps.
- The threads HTTP API (`/api/threads`) and its events on `GET /api/events` (`threads`, `thread:<id>`), documented in docs/threads.md.
- The Mac app's task page is a conversation. Your first task starts one, and every follow-up, its result, a message you send while Mobster works and a question Mobster asks sit in one column, in order, with the approval sheet and the composer docked under it.
- Recent in the sidebar: your 12 newest conversations, each with when it last changed and a dot while a task in it runs, waits for you, or needs a look. Show all opens History, and ⌘K finds conversations by title.
- Steering from the composer: while Mobster's agent works, what you type goes to it at its next step, with "Mobster read this" once it has. A message it never read can run as a new task.
- Clarifying questions, built and off for now: a run that asks for them (`askUser: true`) may get one question from Mobster's agent when the task could mean two things and the screen can't settle it, at most twice a task, shown in the conversation with its answers as buttons, a field and Skip. An answer never approves anything. No surface asks for questions yet; Settings › Advanced › Mobster may ask me questions is the switch for when one does.
- Tell Mobster something while it works: a message to a running task reaches it before its next step, in order, and never approves anything. "Stop after this step" lets the step under way finish, then stops.
- Pause and continue a running task, from the run card in the Mac app or `/pause` in `mobster chat`. Mobster stops between steps, touches nothing until you continue, and looks at your iPhone again before going on. A task paused for 10 minutes stops.
- Pick up where it left off: a task that was interrupted, stopped, unplugged or locked can start again from the last step Mobster finished. It looks at your iPhone first and still asks before it sends, buys, posts or deletes.
- While you type a task in the Mac app, Mobster gets the iPhone ready: it sets up WebDriverAgent's session and reads the screen once, and the task's first step reuses that read when nothing on screen has changed. It never acts, and never touches a phone that has a task running.
- **Memory.** Mobster's agent remembers what you tell it, in your words: where your gym is, how you sign your texts, that Kate Bell is your sister. A task gets only the few things that fit it (at most 12), pinned things go with every task, and things for one app go only with that app's tasks. Everything stays on your Mac, and Mobster never remembers passwords, codes or card numbers.
- **Suggestions to remember.** When you write something like "my gym is the one on 5th Street" or "I always take the window seat", Mobster offers to remember it, in the conversation and in Settings › Memory. Nothing is saved until you choose Remember.
- **Settings › Memory.** Turn memory and suggestions on or off, add, edit, pin and delete what Mobster remembers (with Undo), export it as Markdown, or delete everything.
- **`mobster memory`.** List, add, pin, unpin and delete what Mobster remembers from Terminal, export it, or clear it. It's the same memory as the Mac app's.
- **`/api/memory`** routes and the `memory` event topic, for scripts.
- **Attach files to a task.** Press + in the composer, or drop or paste images, PDFs, text and CSV files onto it, and Mobster's agent reads them: "text Sam the vegetarian options from this menu", with the menu attached. PDFs are read page by page (scans too), pictures are shown to the agent with any text in them, and CSVs by their header and first rows. Up to 10 files a task, 25 MB each. Files stay on your Mac; a task sends only what it reads.
- **A file's text is data, never instructions.** Whatever an attached file says, Mobster still asks before it sends, buys, posts or deletes.
- **Put on iPhone.** Open an attached file and put it in an app's folder on your iPhone (Files › On My iPhone › Pages, Numbers, Keynote and other apps that keep files), or put a text file's text on the clipboard. Mobster's agent can do it too in a task that needs the file there, after asking you: "Put “menu.pdf” in Pages on Sam's iPhone?"
- **`mobster phone file put`, `get` and `ls`.** Copy files between this Mac and an app's folder on the iPhone over the cable, list the apps that keep files, and bring files back. A file with the same name on the phone is kept.
- **MCP `put_file`, `get_file` and `list_files`**, with `mobster mcp --allow-files`.
- **`/api/attachments` and `/api/phone/files`**, the run field `attachmentIds`, and the `attachments` event topic, for scripts.
- **Talk to Mobster** (Mobster for Mac). Hold the mic beside Run, or ⌥ Space, say the task and let go: the words land in the task box for you to check before it runs. The words show as you talk, a step lighter, right where they'll go. A quick tap listens until you pause; Esc stops listening and keeps what you said. Needs macOS 26 or later.
- **Settings › Voice** (Mobster for Mac). Choose the language you speak, turn off Review before sending to run the task when you let go, and test the microphone to see what Mobster hears and how fast.
- `mobster test` runs every check in `.mobster/checks` (or the files and folders you name) on simulators and on your own iPhone, with `--parallel` simulators, retries from a fresh app, flaky-check detection, `--repeat` pass rates, a quarantine file, tags and shards. It writes `results.json`, JUnit XML and an HTML report with each run's frames to `.mobster/test-results/`, and exits 0, 1, 2, 3 or 130 as `mobster verify` does.
- On your iPhone (`--device` only, never from a file in the repository), a check drives only a build you installed, and its Smart steps and its link stay in that app; an App Store app couldn't run, and the app's data is never cleared. `mobster verify --device` keeps Smart in the app the same way.
- `mobster test record --run RUN_ID` turns a finished task into a check, and the Mac app's Copy as check does the same (turn it on in Settings › For developers).
- `mobster mcp` offers `run_tests` and `record_check` to coding agents.
- Check files take `tags`. Guides: Testing your app (`docs/testing.md`) and Running checks in CI (`docs/ci.md`).
- **`mobster mcp install`.** One command adds Mobster's MCP server to Claude Code, Codex, Cursor, VS Code, Claude Desktop, opencode, Gemini CLI, Windsurf, Zed, Goose, Amp, Cline and oh-my-pi, with the absolute path of `mobster` so apps opened from the Dock find it. Files are edited in place with their comments kept and a backup beside them; running it again changes nothing, `--remove` undoes it, and no key is ever written. `mobster mcp clients` lists what's installed and set up, and `mobster mcp doctor` starts the server as a client would and times `initialize`, the tool list and `status` ([MCP server](https://docs.mobster.dev/mcp-server#set-up-your-client)).
- **The mobster skill** (`skills/mobster`, the Agent Skills format): the verify loop, driving a real iPhone, the safety rules and the CLI for clients without MCP. `npx skills add RadishSoftware/mobster` or `mobster mcp install --with-skill` installs it.
- **A Claude Code plugin**: `claude plugin marketplace add RadishSoftware/mobster`, then `claude plugin install mobster@mobster`, adds the server, the skill and `/mobster:verify`. `packaging/mcpb` builds a Claude Desktop bundle.
- `examples/agents/`: Mobster's server in the Claude Agent SDK, the OpenAI Agents SDK, the Vercel AI SDK and LangChain.
- **Several phones at once.** Mobster drives any number of USB iPhones and Mobster simulators, one task per device and tasks on different devices at the same time. `mobster devices` lists them with their state (`ready`, `busy`, `connected`, `needs setup`, `disconnected`), and `--device NAME` (an id, UDID or name) works on `run`, `screen`, `doctor`, `serve`, `mcp`, `verify` and the terminal UI. The first iPhone keeps 127.0.0.1:8100 and 9100; each other iPhone gets its own pair from 8101/9101 up, its own runner build and its own lock. With one phone nothing changes ([Several phones](https://docs.mobster.dev/devices)).
- The API lists the devices (`GET /api/devices`, `GET /api/devices/{id}`) with each one's task and pending approval; a task, a saved task and the history take a `device`; each device has its own live view, control and Setup under `/api/devices/{id}/`.
- `mobster mcp`: `list_devices`, and `device` on every phone tool. With `device` and no `run_id`, `screen`, `tap`, `type_text`, `swipe`, `alert`, `open_url` and the new `launch_app` and `home` drive that device directly, a real USB iPhone included. `verify_start` and `verify` with a device run the check on it.

- **Sign-in codes.** A new agent action, `USE_CODE`, finds a code the phone just received (the keyboard's "From Messages" suggestion, Notification Center, then the Messages list), asks you ("Use the code Chase sent 40 seconds ago to sign in to Chase?") and types it into the code field. The model never sees the code: it is masked in every later step, note and answer, and blurred in screenshots. Code refuses search and message boxes, password, PIN, card and promo fields, Messages, Mail and Notes, an app it can't name, a changed app, two codes without a sender, and codes older than 10 minutes.
- **Notifications.** `READ_NOTIFICATIONS` reads Notification Center read-only (at most 30, in at most 6 seconds), with codes masked, and goes back to the app.
- **`mobster phone`.** `clipboard set` puts up to 64 KB of text on the phone's clipboard, `clipboard get` prints it at the terminal, and `install` installs a signed `.app` or `.ipa` with `xcrun devicectl` (or `simctl` on a Mobster simulator), with plain errors for unsigned builds and Developer Mode.
- **Alerts and keep-awake for schedules.** `MOBSTER_ALERT_WEBHOOK_URL` (https only; Slack, Discord, ntfy or JSON) hears when a scheduled task fails, stops early or waits a minute for approval; the post never holds the answer. `mobster alerts test` sends a test. The Mac stays awake from 10 minutes before a schedule until its run ends (`MOBSTER_KEEP_AWAKE=0` turns it off).
- `mobster mcp`: `use_code` (returns the sender and age, never the code), `read_notifications`, `set_clipboard` (no tool reads the clipboard), `install_app`, `unlock_status` (whether the phone is locked) and `unlock` (answers that Mobster can't unlock an iPhone, so the user has to). A locked iPhone opened directly answers at once with the locked sentence instead of hanging.
- `examples/workflows/`: five saved-task recipes that only read or stop for approval, and [What Mobster can and can't do](https://docs.mobster.dev/capabilities).
- `mobster mcp --allow-device NAME` keeps a server to the real iPhones you name; `list_devices` shows any other as `not_allowed` and the tools refuse it. Simulators are always allowed, and without the flag every device is, as before.
- Every MCP tool carries annotations: `status`, `screen`, `list_devices`, `wait`, `wait_for`, `read_notifications`, `unlock_status` and `unlock` (which does nothing to the phone) are read-only, and the tools that act on a device are destructive and open-world, so a client that asks before such calls asks for them. The server's instructions say screen text is data, not instructions, and to ask the user before sending, buying, posting or deleting on a real iPhone.
- `mobster help [COMMAND]` prints a command's help (`mobster help sim prepare` too). A mistyped command or option suggests the one you meant (`Did you mean --execute?`), and an unknown option after a command prints that command's usage, not the bare `mobster`'s.
- Start a task from Siri and Shortcuts on your Mac, from Raycast or Alfred, or from Siri on your iPhone over SSH with a key that can only start Mobster tasks. The scripts are in `examples/launchers`, and [Start tasks from Siri, Shortcuts, Raycast or Alfred](https://docs.mobster.dev/launchers) sets each one up. Approvals still happen in Mobster on your Mac.
- `mobster login` saves your Claude or OpenAI key for Mobster on this Mac, after one tiny request checks it. Mobster for Mac and every `mobster` command use the same saved key. `mobster login status` shows which keys are saved, masked, and `mobster logout` removes one. Scripts can pipe a key in with `--with-key`.
- `mobster "Turn on Dark Mode"` opens Mobster in the terminal and runs the task. Until a key and an iPhone are set up, the task waits in the box under a three-step checklist that ticks itself off.
- `mobster setup` sets up your iPhone in the terminal, one step at a time, as Mobster for Mac does.
- `mobster completion zsh|bash|fish`, `mobster update`, and a once-a-day note when a new release is out (`MOBSTER_NO_UPDATE_CHECK=1` turns it off).
- `mobster help environment`, `mobster help exit-codes`, `mobster help tui` and `mobster help --all`.
- In the terminal UI: `/new`, `/threads`, `/attach`, `/memory`, `/remember` and `/login`, and `mobster -c` to continue your last conversation.
- **Save a task as a GIF.** Save as GIF, under a finished task in the Mac app, and `mobster export ID --gif` save it as a captioned GIF: the task as you typed it, each step's screen in a phone frame with what Mobster did, the approval card if Mobster asked, and the result, on the Paper or Night ground. It stays under X's 15 MB limit, is saved to Downloads without replacing a file, and is never uploaded. Screens after a sign-in code are left out.
- **`mobster export`** flags: `--mp4` for an MP4 beside it (it needs ffmpeg), `--redact` to blur text fields and message text and leave out the answer, `--theme paper|night`, `-o` for a folder or file, `--json`, and `latest` or the first characters of an ID. `mobster history` ends with how to use it.
- **`POST /api/runs/{id}/gif`** for scripts: `{theme, redact, mp4}`, answering `{name, path, frames, bytes, seconds, mp4}`.
- Steps of Mobster's agent now keep where the text fields and messages on their screen sit (`redact` on the `step` event: frames only, never the text), which `--redact` blurs.
- **Wi-Fi for iPhones, as a preview behind a switch.** After you set up an iPhone with a cable once, Mobster can reach it over Wi-Fi when it's unplugged, through Apple's encrypted link between your Mac and the phone. Mobster's helper on the phone listens only on that link, never on your Wi-Fi (an address this Mac reaches through Wi-Fi is refused), and this Mac's side listens only on 127.0.0.1. Approvals work exactly as on the cable. It's off unless you add `MOBSTER_WIFI_TRANSPORT=1` to your env file; with it off, nothing changes.
- **Use over Wi-Fi in the Mac app**, while the switch is on: a card on Setup's last screen, a row per phone in Settings › Phones, and a Wi-Fi glyph (or Try again) in the iPhone's pane. The pane and the conversation say when a phone is out of reach over Wi-Fi.
- **Networks that keep devices apart are named.** Guest, hotel and campus Wi-Fi often stop devices from seeing each other; Mobster listens for Bonjour for a couple of seconds and says "This network stops devices from seeing each other. Use the cable or your phone's hotspot." in `mobster doctor`, `mobster wifi probe` and the app.
- **`mobster wifi status`, `on`, `off` and `probe`.** See how each iPhone is connected, turn Wi-Fi on or off for one (with the cable, once: the same switch as Xcode's Connect via network), and check the encrypted link to an unplugged phone step by step, including that its Wi-Fi address doesn't answer.
- **`mobster doctor` lines for a phone with Wi-Fi on:** whether Xcode's device service sees it over the network, Developer Mode, the Local Network permission, a VPN warning and whether the network lets devices see each other.
- **`/api/wireless`**, `/api/wireless/network` and `POST /api/devices/{device}/wifi` for scripts, `transport` and `wifi` on each iPhone in `GET /api/devices` while the switch is on, and the `devices` event topic's `transport_changed`.

### Changed

- A task that belongs to a conversation opens there (its old link redirects). Older tasks keep their own page.
- While an approval waits, the composer is off and says to choose above; when an approval or a question appears while you type, focus moves to its heading, and the approval ignores ⌘↵ for its first 700 ms.
- `.mobster/.gitignore` also leaves out `cache/` and `test-results/`; a file an earlier Mobster wrote is brought up to date.
- **Breaking:** options must be spelled in full. argparse took any unambiguous prefix, so `--exec` meant `--execute`, `--al` meant `--allow-app` and `verify --tex` meant `--text`; they are now usage errors that suggest the full option.
- The private vphone pool's `serve --device NAME=SOCKET` is now `serve --vphone NAME=SOCKET`: `--device` names a device everywhere.
- **Breaking:** a check file's `device:` may name only a simulator. A check that names a real iPhone is a usage error (exit 3) unless `mobster verify --device NAME` names it on the command line, so a check file in a repository never drives someone's phone.
- The repository is now `RadishSoftware/mobster`. Links to `RadishSoftware/mobster-cli` redirect.
- Daybreak, the sample app, has a new look in light and dark: a sunrise drawn in SwiftUI on the paywall and onboarding, plan cards with a "Best value" badge on Annual, and a streak card whose sun climbs as you tick off habits. Its accessibility identifiers, deep links, planted bugs and the text its checks look for are unchanged, so every sample check passes and fails as before.
- **Look at your iPhone.** A task you start in Mobster for Mac, the terminal UI or `mobster chat` on a locked iPhone no longer stops at once. Mobster says "Look at your iPhone: unlock it and Mobster starts" (with a notification when the Mac app is in the background) and starts the task the moment you unlock the phone. While it waits it only reads whether the phone is locked: it never unlocks it, taps, types or presses a button, and makes no model call. After 2 minutes it stops with "Still locked, so the task didn't start. Unlock your iPhone and try again." Schedules, `mobster run` and coding agents over MCP still stop at once, and so does a phone that locks during a task.
- `mobster --help` leads with what Mobster does and groups the commands: Get started, Your tasks, Test your app.
- `mobster run` runs on Mobster's agent with just your Claude or OpenAI key. It asks before it sends, buys, posts or deletes; with `--json` or a pipe nobody can answer, so it doesn't. `--engine fast` keeps Quick mode, and `run --demo` runs on the scripted phone with no keys.
- Results read as they do in Mobster for Mac: Done, with what was seen on the screen, or Take a look when nothing on the screen confirmed it.
- `doctor`, `devices` and `mcp clients` print aligned tables with a next step, and stay inside the terminal's width.
- The installer ends with `mobster login`, `mobster`, `mobster mcp install --all` and `mobster test`, and the Homebrew caveats lead with `mobster login`. Homebrew installs on macOS 13 or later, the oldest macOS the binary supports, instead of asking for macOS 15.
- The Agent Skill is `ios-testing` now (`mobster:ios-testing` in the Claude Code plugin). Installing it removes the old `mobster` skill folder.
- The reports `mobster test` and `mobster verify` write look like mobster.dev now, in light and dark, and print cleanly. The top says Passed or Failed, how many checks passed and how long they took, the devices, the command and the date.
- `mobster test`'s report lists each check with its file, tags and a ✓ or ✕ per device. A check that didn't pass opens to the expectation that failed, what Mobster found instead, and the frame that shows it. Filter the list by Didn't pass, Flaky or Passed.
- The overlay frame outlines each asserted element in thin green or red with one numbered pill, placed beside the element where the screen is empty. The report lists the expectations by the same numbers next to the frame. The strip of labels across the bottom of the frame is gone: an expectation with nothing on screen is in the list, with what Mobster found.
- `results.json` keeps each device's expectations from the last attempt (`assertions`: text, held or not, what was found), so the report can show them.

### Fixed

- The MCP tools `unlock_status` and `unlock` no longer describe unlocking an iPhone with a saved passcode, which Mobster never does: `unlock_status` says whether the phone is locked, and `unlock` says plainly that the user has to unlock it. The agent's stop sentence for a locked iPhone no longer offers a Settings › iPhones option that doesn't exist.
- THIRD_PARTY_NOTICES.md no longer says WebDriverAgent is unmodified. It names the upstream project, its BSD-3-Clause licence (with the licence text), the patches Mobster applies to the copy it builds and where they live.
- The installer downloads over HTTPS only (TLS 1.2 or later, redirects included), and its header says what its checks prove. The deployed copy can carry the expected SHA-256 of the version it installs (`DEFAULT_VERSION`, `EXPECTED_SHA256`), so a release replaced on GitHub alone is refused.
- `mobster build-ocr` works in the frozen build: `ocr.swift` is bundled. The build's smoke also runs `--help`, `demo --json` and the terminal UI in a pty (it must leave on ctrl+d).
- Guidance for checking your own app: `mobster doctor` with no phone chosen ends with a pointer to `mobster sim doctor`, which is what `verify` and `mcp` need, and the terminal UI with no iPhone shows a "Checking an iOS app?" block. The simulator advice everywhere is `mobster sim prepare`, then `--device NAME`, not port 8200 (the iOSWorld range) or "outside Mobster". `scripts/usb-wda.sh` is named only in a source checkout, where it exists; an installed build points at the Mac app or `serve --manage-device`.
- Docs: [Configuration](https://docs.mobster.dev/models-and-keys#which-key-does-what) has a table of which key each command needs and rows for `OPENAI_API_KEY`, `ANTHROPIC_API_KEY` and `MOBSTER_SMART_MODEL`; getting started says "model key"; troubleshooting has the installer's fixes (not uv or pipx: Mobster CLI is not on PyPI) and a section for `verify` and `mcp`; the README no longer says `verify` is simulator-only; `version --json` documents `tls`.
- The first WebDriverAgent build (up to 20 minutes), a simulator boot and waiting for WebDriverAgent are never silent: the build's first line names its log and the usual 2 to 5 minutes, and a `Still building WebDriverAgent (2 min 05 s so far)` line follows every 30 seconds. On a terminal `verify` and `sim` redraw it in place; `mobster mcp` sends it as the run's progress message.
- The terminal UI closes cleanly on SIGTERM and SIGHUP (a closed window, `kill`), as on ctrl+d: the terminal gets its main screen, echo, cursor and normal mouse and paste back, and the exit code is 143 or 129. Before, it was left raw.
- `mobster run --json` always ends with a `result` line. ctrl+c, SIGTERM or SIGHUP now stop the task at its next safe point, with `status` `stopped` and exit 130 (143, 129); a second signal forces it and still prints the result. An error before or around the run prints `{"event": "result", "status": "error", …, "exit_code": N}` (`ok` and `error_type` stay), and `demo --json`'s first line is `{"event": "start", …}`. `run --help` says it never asks before acting, and its example no longer sends a text.
- `history -n` takes 1 to 10000 and `serve --port` 0 to 65535 as usage errors (exit 2); `-n 0` printed "No tasks yet", and a huge `-n` or `--port` ended in an OverflowError.
- `mobster mcp` answers every request: a method or tool name with a lone surrogate, or a result JSON can't encode, left the request unanswered with a traceback, and the server then aborted at exit (SIGABRT, exit 134) in most runs.
- An `--env-file` or `$MOBSTER_ENV_FILE` that doesn't exist is no longer silent: every command but `serve` (whose file the Mac app creates) prints `<path> does not exist; no keys or settings were loaded from it`, and `mobster mcp` gives that as the reason Smart is off.
- `mobster verify` with `--json` or in a pipe always prints one result: a usage error in an option before `verify` (`mobster --bogus verify …`, a bad `--wda-url`) exits 3 with a `couldnt_run` usage result instead of 2 ("needs review") and nothing; an unexpected error prints class `internal`; a stopped run prints its result with `exit_code` 130 (143 for SIGTERM). A `--out` that can't be written is a usage error naming `--out`.
- Run folders are readable by you only (0700), and `.mobster/.gitignore` is written whenever it is missing: a phone driven directly through `mobster mcp` made `.mobster/runs` without it, and no later run added it. A real iPhone driven directly keeps its frames in Mobster's data folder unless `--out` or `$MOBSTER_RUNS_DIR` names one.
- Stopping `mobster verify` or `mobster sim` with SIGTERM or SIGHUP (a closed terminal, `kill`, a CI timeout) now stops it as ctrl+c does, with the run's artifacts, and exits 128 + the signal. No stop, signal or exit leaves the first WebDriverAgent build (`xcodebuild`) running, and an MCP run stopped while it waits on that build kills it.
- `mobster chat "Remember that my gym is the one on 5th Street"` with the Mac app or `mobster serve` running now offers to remember it, and `y` or `n` on a terminal answers. It used to wait for a task that never starts, or stop with an error under `--json`. `--json` prints `{"status": "remember", "proposals": [...]}`.
- "Remember that …" no longer runs a task on your iPhone: Mobster offers to remember it.
- Memory reaches tasks you start in the terminal UI and with `mobster run`.
- zsh completion loads.

### Security

- Mobster checks what an attached file is from its first bytes, so a program renamed `menu.pdf` is refused. Files move only to and from apps' own folders, over the cable: never the camera roll, never other apps' data. When the Mac app runs the server, only the app itself can put a file on the phone. A picture the agent sees carries none of the photo's details, so where a photo was taken stays on this Mac. A file dropped anywhere in the app that doesn't take it is refused, never opened in place of the app.
- Speech becomes text on this Mac. The microphone is on only while you talk, nothing is recorded or kept, and Mobster asks for the microphone and speech recognition the first time you tap the mic, never before. Voice never answers an approval: sending, buying, posting or deleting still needs your click or keypress.
- Mobster doesn't automate dating apps. A request to repeat an action over a feed (like, swipe or pass through people, message everyone) ends before any tap in Tinder, Hinge, Bumble, Grindr, Feeld, OkCupid, Match, Coffee Meets Bagel, Raya, Badoo, happn, Hily and Boo, whether the request names the app or the phone is already in it, and it says so plainly. One action there, such as replying to one message, still works and still asks first.
- A loop never judges a person by how they look: their eyes, hair, height, weight, age, skin or attractiveness. Loops over photos, posts, emails and files are unaffected (favourite every photo with a dog, delete every screenshot older than a month). Race, religion, health, disability and sexual orientation were already refused; that now ends the run too, instead of handing the request to the step-by-step agent.
- A repeated action in a dating app is refused for every engine before any tap: "Mobster doesn't automate dating apps." One action there, such as replying to one message, still runs with its approval.
- Tasks another agent starts over MCP can't start in Hinge or Bumble under their App Store bundle ids either.

## 0.2.0 - 2026-10-06

Mobster becomes a tool for checking iOS apps: your agent writes the screen, and `mobster verify` checks it and returns pass or fail with the frames that prove it.

### Added

- **`mobster verify`.** Checks an iOS app on a headless simulator: it installs your `.app`, launches it, optionally opens a deep link and runs steps, then decides the verdict from assertions on the accessibility tree (`text`, `no_text`, `visible`, `absent`, `value`, `count`), never from a model. Exit codes: 0 passed, 1 failed, 2 needs review, 3 couldn't run. Every run writes a folder with `result.json`, a self-contained `report.html`, the frames with an accessibility overlay, and its check as `check.yaml`. Checks can be YAML files (`--check`), flags (`--text`, `--visible`, `--expect` …) or MCP arguments. Steps run in Smart mode on your OpenAI or Anthropic key, capped by `--max-usd`.
- **`mobster mcp`.** An MCP server over stdio, tested with Claude Code; setups for Codex and Cursor. Key-less, the coding agent drives the app with `screen`, `tap`, `type_text`, `swipe`, `alert`, `open_url` and `relaunch`, and `verify_finish` returns the verdict; Mobster calls no model. With a key, `verify` runs the steps itself. Every call returns within 50 seconds, and long work continues under a `run_id`.
- **`mobster sim`.** Mobster creates, boots and reuses its own headless simulators (`Mobster · iPhone 17 Pro · iOS 26.4`), builds the pinned WebDriverAgent once per Xcode version, keeps it on 127.0.0.1, and resets the app between runs. `list`, `prepare`, `doctor`, `shutdown`, `erase`, `delete` and `prune`.
- **Daybreak**, a SwiftUI sample app in `examples/ios/Daybreak` with a three-plan paywall, sample checks, and four bugs to plant: `missing-plan` (also a one-line source change with `scripts/plant-bug.sh`), `annual-price`, `reminder-not-saved` and `stuck-loading`.
- **A standalone binary.** `curl -fsSL https://mobster.dev/install.sh | sh`, or `brew install radishsoftware/tap/mobster`, installs a signed build for Apple silicon that needs no Python. The script checks the download's SHA-256 and signature, installs into `~/.mobster`, links `~/.local/bin/mobster`, and never uses `sudo`. Homebrew installs the same build as a cask and needs no Command Line Tools.
- Docs: getting started with verify, checks, coding agents and simulators.
- **The terminal UI.** `mobster` opens it. You type a task and watch each step, with its target, confidence, timing and what the phone did. Approvals appear inline and take `y` or `n`, the phone's screen shows beside the transcript, and a status line shows the mode, models, spend and cap. It has slash commands (`/app`, `/model`, `/ask`, `/bypass`, `/cap`, `/preview`, `/format`, `/history`, `/resume`, `/device`, `/screen`, `/details`, `/clear`, `/help`), `@app` mentions, history with resume, and a summary printed on exit. It runs the same runtime as `mobster serve` and the Mac app.
- The phone view beside the transcript shows the real screenshot in terminals that draw images (kitty graphics protocol or sixel), and otherwise the screen as Mobster read it, with the element it is about to act on marked. Steps that did not act read calmly ("Looking for a way forward") and consecutive ones collapse into one line with a count.
- `mobster --demo`: the terminal UI with a scripted phone, for trying Mobster without an iPhone, keys or network.
- `mobster doctor`: checks Python, keys, the helper model, Xcode, libimobiledevice, the USB iPhone, the managed WebDriverAgent runner, WebDriverAgent, the lock screen and the device lock, and prints a fix for each problem. `--json` and `--simulator`.
- `mobster history`: lists the terminal UI's past tasks, and works while the UI is open.
- `mobster screen`: shows the phone's screen in the terminal, as real images in kitty, Ghostty, iTerm2 and WezTerm.
- `mobster version` and `mobster tui`.
- `mobster run` prints one readable line per step on a terminal. Piped, or with `--json`, it prints the same JSON lines as before.
- `$MOBSTER_ENV_FILE` sets the default `--env-file`, and `$MOBSTER_WDA_URL` the default `--wda-url`.
- Exit code 3 when no phone answers at the WebDriverAgent address.
- Docs: getting started, device setup, terminal UI, CLI reference, configuration, scripting and the API, architecture, benchmarks and troubleshooting. Also examples, a contributing guide, a security policy and issue forms.

### Changed

- The install script installs the standalone binary instead of installing through uv. If an earlier run installed Mobster with uv, the script stops and asks you to remove that copy first with `uv tool uninstall mobster-cli`.
- `mobster run` no longer requires `--wda-url`. It defaults to `$MOBSTER_WDA_URL`, else `http://127.0.0.1:8100`.
- `mobster --help` and every command's help were rewritten, with examples. The help is pinned by snapshot tests.
- The package depends on Textual for the terminal UI. The Mac app's bundled agent leaves it out.
- The terminal UI's header reads "Mobster CLI" in the text color. Violet stays for what needs you.
- Smart task steps name the row a sideways swipe crossed ("Swiped left on Buy oat milk") and what an icon button does ("Tapped More"). The one-line answer drops a leading "I" before a past-tense verb ("Added the reminder…"); the full answer and `data` stay as written.
- The API sends run frames and app icons with `Cache-Control: no-store`, so no copy of a phone screen outlives its task in a client's cache.

### Fixed

- One line in an env file that Mobster can't read (a space in a name, text that is not UTF-8) no longer stops it. The line is skipped and its number printed to stderr.
- Saving a key into an env file with a line that is not UTF-8 no longer fails with a codec error. The line is kept byte for byte.
- `POST /api/export` answers 403 `downloads_denied` when Mobster may not write to Downloads, instead of 408 "Request timed out".
- HTTPS calls failed certificate verification on a Python with no CA file of its own, such as the Mac app's bundled agent or a python.org install before its "Install Certificates" step. Mobster now verifies against macOS's bundle, `/etc/ssl/cert.pem`, when its Python has none. `SSL_CERT_FILE` and `SSL_CERT_DIR` still win, and `mobster version --json` reports the CA file and how many CAs it loaded.
- `mobster --wda-url URL run …` drove the default phone: an option given before the command was dropped, and so were `--env-file` and `--demo`. `--wda-url` and `--env-file` now reach the command from either side of its name, and `--demo`, `--resume` and `--app`, which only the terminal UI takes, are a usage error with another command.
- `mobster run --execute` on a WebDriverAgent other than port 8100, such as a simulator's on 8203, watched the USB iPhone's screen stream (9100) to tell when the screen had settled. It now watches the stream paired with its own port (8203 to 9203). A port with no pair, below 8100 (such as 8080) or above 64535, has no stream: the run settles by time, and the live view shows screenshots.
- Two processes could drive one phone by writing its address another way (`localhost` for `127.0.0.1`), or by running where `$TMPDIR` differs (ssh, cron). The device lock now names a phone by its host and port and lives in the data folder, and `mobster run` says when another process is using the phone. It also takes the lock that 0.1.0 takes, so a Mac app or CLI not yet updated and an updated one still keep off each other's phone.
- With only an OpenAI key, `mobster doctor` said ready although `mobster run` needs `TYPESAFE_API_KEY`, and `run` found out only after it had contacted the phone. Doctor now warns, and `run` checks the key first and says what it needs. The terminal UI names the Smart model, asks for the key the next task needs, and says that a preview needs a Jev key.
- The terminal UI removed every `@word` from a task, so "Follow @nasa in TikTok" reached the agent as "Follow in TikTok". Only an `@word` that names an app is removed now.
- `mobster --app` with an app installed on the phone but not in the catalog, or with a name no app has, was ignored without a word. It now chooses the installed app, or says there is no app by that name. When the phone's apps cannot be read yet, such as while WebDriverAgent starts, it looks again once the phone is ready, and a task waits for it meanwhile.
- The terminal UI and the Mac app's task composer picked Find My for "Find my boarding pass in Wallet" and Settings for "Message Sam about the camera settings". An app the task works in now comes first, a messaging verb's app beats an app named in the message, and "Find my boarding pass" names no app ("Find my iPhone" still means Find My). When the verb's object is an app, the task runs there: "Call an Uber" in Uber, "Message my Airbnb host" in Airbnb.
- The `@` list put bundle-ID matches first, so `@fa` and tab chose Safari. Apps whose name starts with the letters now come first.
- A Smart task that proved every part of the request (`completed`) read as a grey "Completed". It reads "Done", as a success, in the terminal UI and `mobster history`.
- `mobster run` exited with 1, not 3, when no phone answered in a way other than a refused connection, such as iproxy with no phone behind it, and an invalid `--max-steps`, `--max-seconds`, `--spend-cap-usd`, `--width` or `--wda-url` exited with 1 after contacting the phone. Both now exit as documented: 3 and 2.
- `mobster serve --help` promised a `$MOBSTER_WDA_URL` default that serve never read, and linked a page that does not exist. `serve --port 0` printed port 0 instead of the port it chose.
- `--env-file=~/keys.env` was read with the `~` as typed: the keys did not load, and the terminal UI saved its settings to a new `./~/keys.env`.
- A second terminal UI said "Cannot open the run journal; existing data was not reset". It now says another terminal UI is open.
- Quitting the terminal UI during a task printed "0 ms" for it. The summary now says how long it ran and that it stopped.
